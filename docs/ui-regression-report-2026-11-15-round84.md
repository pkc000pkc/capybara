# Electron 页面回归报告（Round84）

日期：2026-11-15

本轮验证目标是确认遗留研究结果已经进入项目级产物索引，并验证页面上的审核动作能够成功写入、刷新后恢复。

## 结果

| ID | 结果 | 证据 |
|---|---|---|
| H01 | 通过 | qingjian-generated 的“资料来源”页能看到 reconciled 产物，并显示 `available` / `quarantined` 状态。 |
| H02 | 失败 | 点击页面上的“接受”后，状态栏显示 `产物审核失败：Bad Request`。同一运行实例的后端直接请求进一步确认返回 HTTP 414，Fastify 报 `FST_ERR_MAX_PARAM_LENGTH`；长 artifactId 放在 `/:id` 参数中超过默认长度。 |
| H03 | 未执行 | H02 已暴露路由层阻断，继续执行不能证明治理状态闭环。 |
| H04 | 未执行 | 同上，先修复长 ID 路由再验证文件证据反馈。 |

## 新发现的缺口

1. 遗留结果归一化已经能写入 `.capybara/runtime/artifacts/index.json`，但页面把研究结果中的旧列表和项目索引列表直接拼接，产生大量重复产物卡片，治理对象不够明确。
2. Artifact ID 是结构化长标识，当前审核/复核 API 把它作为 Fastify 路径参数，触发默认参数长度限制；页面只能看到泛化的 `Bad Request`。

## 修复前结论

R83 的“旧产物未进入项目索引”问题已部分解决；当前剩余阻断是**长 artifactId 的路由承载方式**，并伴随前端产物去重缺口。修复后需要重新做一轮页面回归，至少覆盖 H02、H03、H04。
