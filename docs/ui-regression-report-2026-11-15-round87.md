# Electron 页面回归报告（Round87）

日期：2026-11-15

## 本轮结论

Round87 已确认项目应用控制面和运行上下文入口可以在 Electron 页面中实际操作。项目应用不是静态占位：页面切换、打开内嵌应用、布局切换、运行上下文和系统设置均能产生可观察状态。

## 发现与判断

1. **应用控制面闭环已经具备可验收形态。** 项目应用页面、来源/产物治理和内嵌浏览器状态之间能够互相解释，应用打开和布局变化也会回写到工作区反馈。
2. **运行上下文的展示层已具备，但当前会话数据为空。** qingjian-generated 的历史应用生命周期收据能进入“证据治理”，而当前会话的时间线、工具进程和子智能体为空。这说明视图切换正常，但“当前任务产生的 trace 在会话中实时增长”仍需要用一次真实运行验证。
3. **设置页已经暴露出系统级资源边界。** 页面明确显示全局密钥保存在系统用户 `.capybara`，工具/Skill 同时展示项目资源和系统回退来源，符合此前约定的分层加载方向。
4. **产物列表仍然很长。** 同一研究闭环的多个历史版本同时可见，虽然相同 `artifactId` 的重复卡片已被去重，但版本列表的分组、筛选和历史任务归属仍不够清晰。

## 仍需补齐的阶段性缺口

- **真实运行 Trace。** 需要在当前 Electron 页面发起一次能调用工具的任务，确认“模型阶段摘要 → 工具调用 → 结果 → 验证 → 最终回复”实时进入时间线，并在重开页面后可回放。
- **进程和子智能体非空态。** 当前只验证了两个空状态；还缺工具进程、脚本进程和子智能体运行中的页面证据。
- **错误态页面。** 还需要覆盖工具超时、权限拒绝、模型失败和应用启动失败，并确认阶段、耗时、requestId/turnId/stepId/callId 与错误原因一致。
- **设置关闭回退。** 设置页的打开和内容已验证，但关闭后是否准确回到原项目应用页、是否保留当前滚动/标签状态还未形成证据。
- **应用生命周期收据与任务 Trace 的关联。** 目前证据治理能列出 29 条应用收据，但这些收据尚未在当前会话时间线中显示跨层关联关系。

## 建议下一轮

下一轮应创建一个最小、可控、会调用 `list_files` 和 `read_file` 的真实任务，在同一会话中验证非空时间线、工具进程、结果证据和最终回复；随后刷新或重新打开项目，检查 SQLite/Trace 回放是否保持同一组关联 ID。完成这一步后，才能判断“实时、可验证、可回放”的核心目标是否真正闭环。

## 工程验证补充

执行 `npm run verify:desktop-runtime --workspace=apps/workbench` 通过。脚本输出包含 `terminal=chat.assistant.completed`、`traceEvents=82`，并确认 `hasContextDocument`、`hasContextControl`、`hasCandidates`、`hasEvidenceReceipts` 均为 true。该结果证明运行时协议和回放数据在脚本级别已经能产生；当前仍缺少的是把这类非空轨迹在 Electron 当前会话中实时展示并在页面重开后复现。
