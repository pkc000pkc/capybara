# Capybara Workbench 阶段性 Review 与回归报告（2026-11-14 第九轮）

本轮继续按桌面黑盒方式回归，重点验证浏览器研究和长上下文场景。测试前完成了运行时修复，随后用标准 Electron 命令启动，创建新会话并从页面发送真实请求。

## 本轮新增修复

### 浏览器读取稳定性

- HTTP 浏览器读取允许跟随公开页面的重定向，最终 URL 保留在 evidence 中。
- 同一会话内同一 URL 成功读取后复用已有 evidence。
- 同一 URL 已返回 404、网络失败或其他未知状态后，重复请求会直接返回“不要重试原 URL，请选择其他来源”，避免模型陷入重复读取。
- 404、状态码和恢复建议会出现在页面工具结果中。

### 上下文确定性投影

模型请求现在按输入预算组装：

- 固定系统提示词和工具定义先占用预算。
- 历史消息按最近的完整消息组保留。
- assistant 工具调用和对应 tool 结果必须成组保留。
- 过旧历史不会继续挤占当前任务和项目上下文。
- 只有固定系统/工具 envelope 本身超限时才报告固定上下文错误。

## 当前缺口

### P1：项目应用实例状态仍需统一

- 市场研究发布实例与项目应用面板可能仍不是同一个 instanceId。
- 停止后重启可能出现“需恢复”，健康 PID 与页面状态不一致。

这不影响本轮 H01/H04，但仍阻塞 H05 的完整验收。

### P1：研报产物确认仍不完整

研报下载已有来源、时间、哈希和 evidence，但仍处于 quarantined；完整性、可读性和语义可用性还没有进入最终 accepted 状态。

### P2：部分控制面仍是占位入口

深色外观、能力演化、Token 用量、关于概念稿等入口仍显示占位提示。项目关闭恢复、完整资源安装后的重新运行验证也需要继续覆盖。

### P2：旧失败会话的恢复展示

重启后如果默认选中之前失败的会话，页面会保留该失败记录；创建新会话可以正常工作。后续可以进一步优化默认选中策略和失败会话的恢复提示，但不再阻塞新任务执行。
