# UI 黑盒回归计划（Round 35）

日期：2026-11-14  
范围：设置菜单可达性、空输入校验、扩展资源入口和菜单状态反馈

## 目标

Round34 证明设置菜单项可见但无法形成有效页面转移。本轮只验证菜单激活路径和设置页面的空输入边界，测试期间不修改代码。

## 用例

| 编号 | 页面操作 | 预期 |
| --- | --- | --- |
| R35-01 | 从工作区焦点、顶部工具按钮焦点、快捷键三种路径打开工具菜单，并激活“设置” | 至少有一种标准页面操作进入设置；失败时必须有明确反馈 |
| R35-02 | 进入设置后，不填写 GitHub 仓库和 Skill 路径，点击预览 Skill | 显示明确空输入校验或失败原因，不静默 |
| R35-03 | 进入设置后，不填写插件目录，点击预览/安装插件 | 显示明确空输入校验或失败原因，不生成半成品资源 |
| R35-04 | 在设置页关闭后重新打开工具菜单和设置 | 设置内容、全局模型状态和资源列表可恢复，项目工作区不串线 |
| R35-05 | 返回工作区后重新打开应用面板和运行上下文 | 设置操作不改变应用实例、会话轨迹和证据治理状态 |

## 判定规则

- 只以页面实际可见反馈判定，不用代码或缓存替代页面证据。
- 菜单项“可见”不等于“可用”；必须观察到页面转移、对话框或明确失败提示。
- 完成整轮后再决定是否需要局部修复。
