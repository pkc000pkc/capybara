## 新增缺口

1. **项目资源 API 失败没有产品级错误映射**：非法资源请求暴露原始 `capybara:project-api` 和 `TypeError: fetch failed`。
2. **Skill/插件路径校验没有真正发生在页面语义层**：用户看不到仓库不存在、路径不存在、manifest 缺失或项目边界拒绝等具体原因。
3. **设置重开会携带项目资源读取失败状态**：全局配置成功与项目资源失败虽有一句说明，但变量、资源列表和 revision 的可用性没有清晰分区。

## 下一轮建议

- 先修正 project-api 的连接/错误映射链路，让预览接口返回结构化资源错误。
- 对 Skill 和插件分别展示仓库、路径、manifest、边界和网络阶段的失败原因。
- 设置重开时把全局配置、项目变量、项目资源目录分成独立加载状态，避免一处失败污染整个资源面板。
