## 黑盒证据

### R26-01：发送只读命令并观察过程

- 用户指令：要求只运行一个只读命令，在项目根目录执行 `pwd` 或等价命令。
- 时间线显示：模型解析阶段、`run_command` 工具调用、工具结果回传模型三个阶段。
- 工具调用收据：`call_00_UW5qtEHHrc70aqKMbGjy5555`，工具状态为 `succeeded`，实际命令因 Windows `cmd` 不支持 `pwd` 而以 `exitCode=1` 结束。
- 最终回复如实说明了 stdout 为空、stderr 原因和无法取得具体路径，没有把 `cwd: "."` 冒充成绝对路径事实。

### R26-02：进程页签表达执行边界

- 运行上下文可打开并切换到“进程”页签。
- 进程列表显示 `delegate_task`、`list_files` 和本次 `run_command`，每条包含工具名、起止时间、完成状态。
- `run_command` 条目显示 `执行边界：project · cwd .`。
- 页面没有显示项目绝对路径、系统用户目录或临时目录路径。

### R26-03：重新打开运行上下文

- 关闭并重新打开运行上下文后，进程计数仍为 3。
- `run_command` 进程条目和 `project · cwd .` 字段从已保存的运行快照恢复，和聊天区收据中的 `cwd` 参数一致。

## 发现与边界

本轮关闭了“项目目录执行时页面无法表达结果归属”的缺口。当前验证覆盖的是项目相对目录；临时目录、系统目录的能力门禁、拒绝原因和跨目录结果归属仍需单独设计并回归。工具结果本身仍按宿主 shell 语义执行，Windows `cmd` 下不能直接使用 Unix `pwd`，页面已正确呈现该失败事实。
