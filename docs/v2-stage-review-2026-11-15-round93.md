# V2 阶段性工作审查（Round93）

日期：2026-11-15

## 本轮确认

路径安全门禁和失败恢复已经通过页面验证。运行时在文件访问之前检查规范化路径是否仍在项目工作区内，越界请求直接返回失败收据，不泄露工作区外内容；失败之后，新的无工具请求可以立即完成。

## 当前阶段能力

- 普通命令可以在不显式指定 `timeout_ms` 时正常执行。
- 工具收据包含成功/失败状态、耗时、进程耗时、退出码、stdout/stderr、`callId` 和 `stepId`。
- 越界路径以明确错误 `path must stay inside the project workspace` 收束。
- 越界失败不会触发无效重试，也不会阻塞后续会话请求。

## 新的缺口

### 默认 timeout 仍不可审计

未显式传递 timeout 的调用只返回 `timedOut=false`，没有返回实际应用的默认 timeout 数值，也没有在执行过程卡片中显示“配置来源/生效值”。因此可以验证默认策略没有阻止短命令，却不能验证默认值是否符合设计或项目配置。

### 失败类型仍未统一

不存在文件返回 `ENOENT`，越界路径返回 `path must stay inside the project workspace`，两者都映射为 `RUNNER_FAILED`。当前页面能读懂错误，但上层治理还缺少稳定的分类字段，例如 `PATH_OUTSIDE_WORKSPACE`、`FILE_NOT_FOUND`，不利于统计和重试策略判断。

### 运行上下文还需要按事件链路筛选

当前会话卡片已经能显示 `callId`、`stepId` 和 artifact，但跨父子任务、失败类型和恢复请求的统一筛选仍未形成独立视图。

## 阶段判断

主链路、A2A 成功链路、失败收束和路径安全已经达到可演示和可继续验收的水平。下一步应优先让运行时收据带出实际 timeout 来源和值，并统一工具失败分类，然后补权限拒绝、子代理失败/超时、应用启动失败三类场景。
