# V2 提示词评审场景：规划、能力与任务状态

日期 2026-11-20。本文定义提示词和运行协议的预期行为，实际执行证据见统一验收记录。示例中使用概念名称，运行时 ID、状态枚举、工具名称与 schema 均由宿主提供。

## 1. 复杂任务先规划，按阶段使用能力

用户要求：“检查退款服务最近的失败原因，核对订单与邮件证据，给出报告。先调查，不发送邮件、不执行退款。”

| 真实条件 | 主模型应提出什么 | 运行时应产生什么 |
| --- | --- | --- |
| 已有足够项目背景，当前为纯规划轮 | `propose_plan`，按依赖拆分查询失败记录、核对两方证据和验证报告。把计划中的查询写入 `capabilityIds` 和 `completionConditions`，尚无回执时引用列表填 `[]` | 校验并保存计划。下一轮按就绪节点投影工具 |
| 下一轮需要读取记录 | 当前投影允许的读取/检索调用 | 请求绑定下的真实调用与收据；不因接受计划授予外部写权限 |
| 计划引用了尚未发生的调用，或把 `propose_diff` 填成已执行动作 | 收到拒绝后用当前绑定重提。保留已经登记的义务，从真正的成功结果取新增引用 | 保留原计划修订，并将拒绝关联到原始响应。修复耗尽时给出失败原因 |
| 读取成功并已登记来源 | 修订节点，引用真实 `call:` 回执和需要的已登记证据 | 核验节点条件、依赖与引用后接受状态变更 |
| 目录中存在未投影能力 | 使用宿主提供的发现/加载入口，或说明具体缺口 | 校验后为后续请求提供必要 schema；目录名称不等于可执行能力 |
| 从调查进入验证阶段 | 使用新快照与新能力投影 | 旧 request/版本的动作重新校验，不能照搬上一轮工具权限 |

报告中的金额分歧由主模型分析。整理器只按来源保留材料，不替主模型决定哪一方正确。是否完成报告仍由真实完成条件和证据判断。

## 2. 人工问题可见，回复恢复原任务

订单查询缺少必要租户标识，其他日志检查仍可独立推进。主模型先推进独立节点，确实需要用户输入时提出一个明确问题，并通过 blockingTaskIds 标明受影响节点。

运行时创建 humanRequestId 并保存用户可见问题。用户回复与该请求、原 task/run 关联；重连后继续原工作，保留已成功的查询，不重复执行已有成功收据的动作。重复或过期回复不自动作用于新任务，用户没有回复也不构成默认授权。

检查点：问题展示、关联身份、局部阻塞、重启恢复和执行去重分别验证。仅看到 paused 字段不足以证明闭环。

## 3. 等待真实信号，超时不等于成功

已经发出一个有真实句柄的只读查询，结果尚未返回。没有可独立推进节点时，主模型引用该句柄及宿主支持的条件提出 wait；不能自行编造 queryId、期限或事件时间。

运行时先保存订阅与截止条件，再进入等待。结果事件或超时事件唤醒原任务，去重后生成新快照。模型重新判断：收到结果则验证；超时则检查查询是否仍在运行或结果未知，再决定重试、求助或继续等待。

关闭桌面再恢复时不能重复订阅或把“窗口关闭过”当作信号。轮次结束、自然语言“已等待”和模型自报时间不能结束有效等待。

## 4. 子结果是材料，生命周期由宿主证明

父层委派“只读核对订单来源”的局部任务，授予相关读取能力及局部上下文，取得真实 child/task 句柄。

子代理返回结果与证据包后，父层分别核对子任务身份、工具收据、结果范围和未完成项；需要写入父文档的内容先变成候选，再走 diff。导入一份文本不能生成 succeeded，也不能改变父任务权限。

生命周期成功、证据可用和父层已消费结果是不同记录。必要子结果未消费时，父任务不能正常完成；子任务被取消、超时或迟到的结果保留真实状态。只读子代理不能通过 Skill 脚本、内部工具、资源或 Hook 间接写入。

## 5. 未知写入先核对，所有完成入口同门禁

独立的已授权写入场景中，某次操作超时，尚无成功或失败证明。主模型不能立即重复操作，也不能把超时当作已完成。应先按真实操作身份查询结果；无法确定且影响继续工作时提出必要的人类协助。

即使本轮 completionCheck 没有列出该操作，运行时仍检查整个任务账本。旧 completed 输出、工具正文“成功”以及新 finish 请求都不能绕过未知副作用、未消费子结果、人工请求和有效等待。取消或预算耗尽报告部分结果与终止原因，不包装成成功。

同一任务补齐证据、结算操作并交付全部约定内容后，主模型应在首次满足完成条件的轮次提出 `finish`，使用当前绑定和真实回执。若还有明确可推进的义务，`continue` 应关联下一项工作。验收对照用户可见结果、续轮前后的实际进展、账本和总用量，记录重复同一答复产生的额外轮次。

真实模型的配对验收分别记录三类完成拒绝：报告字段携带未定义属性、缺少 `completionCheck`、仍存在阻塞不确定性。修复应明确对应原因，保留已接受义务和真实阻塞。只需交给负责人判断的分歧随最终答复呈现。按相同场景比较首次接受的轮次、修复后是否完成以及原件补读次数。

## 6. 文档更新与任务状态分别演进

在退款排查中，Organizer 从 cache 提取订单系统 A 的 125 USD 与邮件 B 的 120 USD，形成并列来源的会话 diff；无关天气材料可以提出可召回的归档建议。

| 事件 | 文档与下一轮输入 | 任务与训练记录 |
| --- | --- | --- |
| 两级更新均提交成功 | 新 revision 与真实 receipt；符合覆盖条件的历史才退出重复投影 | 任务仍按原完成条件运行；记录模型提案与宿主结果 |
| 当前计划包含两个有依赖的文档编辑节点 | 第一项 diff 绑定当前活动节点。修改提交后，下一轮带所属节点和 `completionActionRef` | 用 `complete_plan_nodes` 提交第一项节点及其回执。第二个节点出现在活动列表后，再提交该节点的编辑。回放与回滚均可追溯至原件。 |
| 任一作用域校验或持久化失败 | 整批不局部生效，原材料仍可用，覆盖边界不前移 | 保留原提案和拒绝原因，不生成成功标签 |
| 项目知识处于训练冻结状态 | 项目正文只读；新材料可进入会话或待评审建议 | 不因训练/梦境角色改变冻结状态 |
| 前台更新后梦境提交旧版本 | 拒绝或重新读取后提出新提案 | 空闲角色不能越过 revision 或证据门禁 |
| 整理器输出合法 JSON，但删掉 B 的否定/条件 | 语义验收失败，保留原材料并纠正 | JSON 合法率不能代替信息保真或业务效果 |

最终分别核对实际发出的模型输入、文档/状态持久化、V2 Electron 展示和后续任务质量。样例中的期望输出不能当作真实执行证据。

## 7. 能力变化后的恢复不重放旧动作

模型提出“写入结果，再读取验证”。两项调用最初在同一个合法投影中；写入取得真实成功收据后，读取权限被撤销。

运行时保留写入结果，把尚未分发的读取记录为 `dispatched=false` 的拒绝，补齐原工具组，再发布新的能力与状态投影。主模型看到新投影中读取不可用，可以提出必要协助；不能重新执行已经成功的写入，也不能把读取拒绝当成验证完成。Workflow 场景同样返回真实部分结果，分别保留 completed、failed 与 skipped。

若变更的是 manifest、参数 schema 或 runner，下一轮工具定义与校验器必须同步刷新。模型重新构造一个新调用，旧参数不会被宿主自动转换或重试。若推理期间状态变化，旧模型回复只保留作轨迹，使用新绑定重新决策。

关闭重连保留同一 task/run、恢复次数、拒绝记录和真实结果；人工回复不重置恢复预算。反复变化耗尽预算时真实失败，不能无限续轮。伪造投影或绑定仍直接拒绝；未知副作用先核查，取消或关闭后不再调度新模型请求。

## 8. 同一运行中的授权、委派与交付

用户要求核查退款记录并准备只读报告。附件读取和能力搜索已获准，提交汇总报告前需要用户确认。项目已有跨会话的来源标注规则；订单金额、两份材料的分歧和本次授权均属于当前会话。[上下文输入与预期文档](review-scenario.md)

| 检查点 | 模型应有的行为 | 验收记录 |
| --- | --- | --- |
| 独立规划 | 提交人工确认、读取附件和能力调查等独立节点。把交付前能核验的工作写入计划，把报告文本留给 `finish` | 规划轮工具列表为空。宿主接受依赖图，`human_input` 节点的能力清单为空 |
| 授权待回复 | 在确认节点提一个具体问题，推进独立读取与搜索。子代理只在获授范围查找所需资料 | 人工请求已保存，原生工具投影随节点变化，真实 Child 搜索及父层审核发生在答复前 |
| 资料整理 | 把两份来源的金额、条件与出处并列写入 session，按项目锚点保留已批准的项目规则。明显无关资料可从原件召回 | 两份文档的 revisions、局部 diff、原件与证据回执各自可核对。必要字段齐全时才推进相应历史覆盖 |
| 保存和恢复 | 只剩确认义务时由宿主暂停。重开后读取原问题与已核验的材料，按用户真实回复判断交付许可 | 原 task/run、人工请求 ID、子结果消费与文档 revision 均可恢复。`human:` 回执只结算原计划节点 |
| 授权回复追加归档回填 | 先验收原人工节点，再把回填纳入计划。用当前 session 的归档来源召回 N-41，按原句向「审计索引」新增条目。若归档为空，保留未结义务，并核对有权读取的原件和归档处置 | 核对授权前实际存在的归档回执、`source_archive` 命中、候选和目标章节。以该编辑节点自己的 `context:` 回执验收。其他信息区的命中单独记录 |
| 正常交付 | 获准后按既有材料交付只读报告，呈现来源分歧和未得业务授权的动作 | 真实 `finish` 通过完成门禁。报告完整覆盖用户要求，引用可回读，项目文档未接收会话私有内容 |

再分别验收拒绝授权、错用前置节点回执与子代理超时。拒绝答复结算人工请求，但交付或动作仍按实际授权范围处理。将 `human:` 或 `context:` 回执用于其他节点时，宿主拒绝且保留原计划；后续节点通过 `dependsOn` 继承前置结算。超时结果保留原状态，父层可按审核回执接管，取得实际成功动作后再验收原节点。分支结果、用户答复和父任务完成分别核对。

正常路径以真实主模型、整理模型和真实委派在同一个 task/run 的记录为准。受控回放用来验证越权、重连、错误通道和拒绝路径；冻结同一份项目上下文，另起会话验证项目知识可用及会话私有信息隔离。
