## 本轮确认的缺口

### P1：快速新建会话仍可产生重复会话

复现步骤：

1. 打开一个只含一条初始会话的干净项目。
2. 连续发送两次 `Ctrl+N`。
3. 左侧出现两条独立的“新会话”。

影响：会话列表会被重复空会话污染，和“发送一次只创建一次”的产品预期不符。需要检查键盘事件路径是否绕过了同一单飞保护，以及创建完成前是否存在状态快照竞争。

### P1：干净项目打开设置时显示项目资源读取失败

设置面板显示：

> 项目提示词变量、项目资源目录读取失败。全局模型配置已正常读取，聊天与过程记录可继续使用。

但同一面板仍能列出系统工具、Skill 和 harness 条目。对用户而言，这会造成“资源已显示但目录读取失败”的矛盾状态，应在下一轮确认是空项目初始化时序问题、路径回退问题，还是告警范围过宽。

### P2：文件菜单的项目文件、导出项目快照缺少可观察结果

菜单项存在，但本轮没有形成成功 toast、对话框、下载路径或状态变化。它们至少需要给出可验证的结果反馈，不能只完成菜单关闭。

### P2：工具菜单三个入口仍为占位状态

定时与触发、能力演化、Token 用量均能点击，但只显示“入口已保留，当前项目暂无可执行内容”。这不是页面崩溃，但从产品闭环看，用户无法继续进入对应管理视图，也无法判断“暂无数据”和“功能未接入”的区别。

## 已确认的正常能力

- 可通过原生目录选择器打开空项目，项目名称、空目录状态和工作区提示同步更新。
- 项目切换不会丢失原项目的历史会话和应用面板。
- 运行上下文面板可从协作任务、进程管理、本地运行与恢复入口打开，并显示时间线、进程、子智能体、Runtime、上下文范围、候选信息与证据计数。
- 设置面板可读取系统级模型配置；DeepSeek 提供方、模型、Chat Completions 协议、Base URL 和“全局密钥已配置”均可见。
- 资源条目已经展示 kind 和 source，两个同名 harness 可以区分来源。

## 下一轮建议

1. 先修复键盘 `Ctrl+N` 与按钮点击共用的单飞/防抖路径，并在同一个干净项目上重新计数。
2. 再确认空项目 `.capybara` 初始化完成后，设置面板的资源读取告警是否消失；若仍存在，缩小告警范围并明确回退来源。
3. 单独验收项目文件、导出项目快照的可观察结果。
4. 对定时、能力演化、Token 用量入口给出真实面板或明确的不可用状态，而不是泛化占位文案。
5. 继续覆盖高风险运行场景：工具超时、脚本非零退出、真实子智能体、断线重连、应用更新回滚。

## 结论

Round 16 证明了项目打开、项目切换、设置资源展示和运行上下文入口已经具备可用页面闭环；同时确认了重复新会话是当前仍可复现的真实缺陷，项目资源读取告警和多个占位入口是下一阶段产品化验收的主要缺口。本轮不应据此宣称全量回归通过。
