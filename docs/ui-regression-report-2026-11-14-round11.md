# UI 回归报告（2026-11-14 · Round 11）

## 测试目的

验证新版市场研究结果在项目应用中的动态投影、内容与资料来源页、内嵌应用入口，以及桌面应用重启后的会话恢复行为。

本轮仍以页面点击和可见结果为准，不以代码级测试替代页面验收。

## 测试环境

- 启动方式：`npm run desktop:start --workspace=apps/workbench`
- 应用：Capybara Workbench（Electron）
- 项目：`capybara`
- 研究对象：`000682`
- 研究结果：market_data、report_download、python_analysis、dashboard_publish、dashboard_open 均为 `succeeded`

## 测试结果

### 1. 研究结果动态投影：通过

项目应用面板显示动态标题 `000682 行情看板`、`v1 · 已发布`，并展示：

- 研究闭环状态与五个研究步骤；
- 区间收盘价变化 `-6.19%`；
- 年化日收益波动率估计 `39.24%`；
- 建议立场 `negative（待人工审查）`；
- 不确定性和人工核对提示。

### 2. 内容与数据页：通过

点击“内容与数据”后，页面显示研究内容和结论，包括官方来源的原文要点、不确定性、综合结论和未覆盖部分。

### 3. 资料来源页：通过

点击“资料来源”后，页面显示 Eastmoney 行情来源、三份研报下载记录、Python 进程退出结果、应用运行时 receipt、看板 host 和 publisher 记录。

### 4. 同一进程打开内嵌行情看板：通过

点击“打开应用”后，Capybara 内嵌浏览器显示 `000682 行情看板`，可见：

- 最近 30 个交易日数据；
- `bar_count=21`、`report_count=3`；
- 区间收益与年化波动率；
- 交易建议及风险/不确定性；
- 日线表格和三份研报链接。

点击顶部“关闭应用视图”后返回项目工作区。

### 5. 重启后会话与研究结果恢复：通过

关闭并按标准命令重新启动 Electron 后，项目会话、研究结果、动态应用标题、版本、步骤、证据和产物均恢复显示，说明结果持久化已经生效。

## 已发现缺口

### P1：持久化了临时 host 地址，重启后无法重新打开看板

重启后应用面板仍显示上一轮生成的地址，例如：

`http://127.0.0.1:52552/applications/market-dashboard/v1/index.html`

点击“打开应用”后页面进入 `chrome-error://chromewebdata/`，工作区出现：

`Error invoking remote method 'capybara:open-application': Error: ERR_CONNECTION_REFUSED (-102)`

根因是本地 dashboard host 随 backend/Electron 进程退出而消失，但持久化结果仍把旧地址当成可用地址。

### P2：逻辑应用状态和 supervisor 运行状态仍有两个来源

研究结果显示“本地应用运行：运行中”，而应用面板顶部显示“已停止”。这两个状态分别来自逻辑研究结果和当前 supervisor 实例，用户容易把它们理解为矛盾状态。

## 本轮结论

研究结果的页面表达、来源与证据投影、内嵌浏览器打开/关闭，以及跨重启的结果恢复已经达到可验收水平。

看板地址的生命周期还没有闭环：结果可以恢复，但重启后不能直接恢复一个可访问的本地 host。下一轮应优先处理 host 重建或把持久化状态标记为“需重新发布”，再重新回归“重启 → 打开应用”场景。
