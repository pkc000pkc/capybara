# Capybara Workbench 阶段性 Review 与回归报告（2026-11-14 第七轮）

本轮是在第六轮问题沉淀后，完成一项前端局部修复，再按同一套桌面黑盒用例进行复测。测试前已记录测试用例，本轮通过 Electron 页面点击、观察和应用内状态确认结果，没有用代码级断言替代页面验收。

## 本轮完成的修复

项目应用面板的页签名称已固定为：

- 总览
- 内容与数据
- 资料来源

修复位置：apps/workbench/src/app/page.tsx

此前同一页签会根据市场研究数据动态显示“分析结果”，导致页面契约不稳定，也让用户、测试和回放无法依赖固定入口。本轮重新构建并用标准桌面命令启动后，空白会话和项目应用面板均显示稳定页签；点击“内容与数据”可正常切换，页面没有报错。

这些入口的页面反馈正常，但资源实际加载和普通会话中的工具激活仍未形成稳定闭环。

## 当前缺口分级

### P0：阻塞核心任务验收

#### 1. 普通请求没有稳定激活文件、Python 和运行工具

在“写文件并运行 Python”的实际页面场景中，Agent 只看到 harness 类能力，无法稳定获得项目文件、写文件、读文件和命令执行工具。即使系统资源目录中存在工具清单，普通请求没有自动完成搜索、加载和注入。

影响：

- H04 编写并运行 Python 仍失败。
- H05 看板生成依赖人工或预置能力，不能证明 Agent 能从普通指令完成产物链。
- 文件读取、写入、执行和验证无法形成可回放闭环。

这是当前最大缺口，优先级高于继续扩展 UI 入口。

#### 2. 上下文预算和浏览器调研闭环仍不稳定

股票调研场景仍有浏览器读取 404、重复读取以及上下文超过限制的问题。页面可以展示错误，但不能稳定完成“搜索—提取—去重—证据—结论”的长流程。

影响：

- H01 仍未通过。
- 多来源研报和行情数据合并时，容易在中途丢失上下文或重复工具调用。

需要在运行时层控制候选结果体积、重复读取和证据摘要，而不是只在页面增加提示。

### P1：业务结果可见但状态或证据不完整

#### 3. 项目应用实例和市场研究发布实例可能不是同一个实例

市场研究看板可以发布并在内嵌浏览器打开，但右侧项目应用面板可能仍显示另一个空白应用实例；健康检查使用的实例 ID 也出现过找不到的情况。

影响：

- 用户看到的“已启动”可能对应另一份应用。
- 应用停止、重启、健康检查和打开入口不能保证作用于同一进程。

需要统一 applicationId、instanceId、版本和项目绑定关系，并让面板、运行管理和内嵌浏览器都使用同一实例状态。

#### 4. 重启状态机没有一次性收敛

停止后点击重启可能显示“需恢复”，但同时存在健康 PID；用户还需要再次点击启动，才能回到运行中。

影响：

- 用户无法判断重启是否成功。
- UI 状态、进程状态和健康检查结果互相矛盾。

需要把启动、健康检查、恢复、失败和运行统一成明确状态机，并由同一个实例返回最终状态。

#### 5. 研报下载结果仍处于隔离态

三年研报下载已经有文件、来源、日期、哈希和 evidence，但产物仍标记为 quarantined，缺少覆盖完整性和语义可用性的最终核验。

影响：

- 下载动作可见，但用户不能把结果视为已确认资料。
- H02 只能算部分通过。

### P2：产品化完整度不足

#### 6. 原生菜单中仍有占位入口

深色外观、能力演化、Token 用量、关于概念稿等入口可以点击并显示占位提示，但没有实际页面或能力。

这不阻塞当前运行时主链路，但如果作为产品功能验收，仍不能算通过。

#### 7. 应用内容页当前只有稳定入口，内容模型仍偏演示

“内容与数据”标签已经稳定，但空应用状态仍主要是说明和待核对清单。真实应用生成、版本差异、内容来源和运行产物的关联还需要由 H04/H05 业务链路证明。

#### 8. UI 回归用例中仍有部分场景未完全通过

根据既有用例集：

- B01/B02 新会话和重复点击需要继续确认只创建一次及选中一致性。
- B08/B09 关闭项目后恢复项目需要继续确认历史会话、应用实例和项目级 .capybara 状态不串。
- D05-D07 需要在工具激活修复后重新执行。
- E02-E09 需要继续检查阶段摘要、证据、候选治理和重启回放。
- G03-G08 需要从“入口可见”推进到“实际保存、加载、项目优先/系统回退和重新运行有效”。

## 阶段性结论

当前工作已经达到“页面控制面可用、运行轨迹可观察、项目应用入口可操作”的阶段，但还没有达到核心业务闭环可验收的水平。

可以确认的成果：

- Electron 单体启动和页面基本结构稳定。
- 原生菜单、项目应用、运行上下文和设置入口可用。
- 工具过程、进程状态和空子代理状态可见。
- 应用页签契约已修复并通过重新构建后的页面复测。
- 内嵌浏览器应用可打开和关闭。

尚未达成的关键目标：

- 普通会话自动获得并使用文件、Python、命令执行能力。
- 浏览器调研在长上下文下稳定完成。
- 生成应用与项目应用面板使用同一个实例。
- 重启、健康检查和 UI 状态一致收敛。
- 下载资料从隔离态进入可确认、可使用状态。
- 全部页面按钮从占位入口进入真实功能或明确的产品状态。

建议下一阶段只优先处理两件事：先修复工具激活和上下文预算，再重新执行 H01/H04/H05；随后统一应用实例状态机并复测 F05-F10。这样能最快判断系统是否已经从“可演示的工作台”进入“可完成真实任务的工作台”。
