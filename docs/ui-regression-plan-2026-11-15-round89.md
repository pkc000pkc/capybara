# Electron 页面回归计划（Round89）

日期：2026-11-15

本轮目标：验证桌面进程冷启动回放和工具超时错误态。

## 用例

| ID | 场景 | 操作 | 预期 |
|---|---|---|---|
| N01 | Electron 冷启动回放 | 关闭当前 Electron 窗口，使用标准 `npm run desktop:start --workspace=apps/workbench` 重新启动，重新选择 qingjian-generated | 已完成的只读会话、消息和项目应用状态仍可见。 |
| N02 | 冷启动后的运行上下文 | 在重启后的同一项目打开“查看运行上下文” | 时间线、进程、证据治理仍保留 Round88 的非空计数和结果。 |
| N03 | 工具超时错误态 | 发送“运行一个明确会超时的最小 Python 脚本，等待 30 秒，要求按当前超时策略停止并报告原因；不要修改项目” | 页面显示运行中、超时/失败、耗时、进程收束和最终错误说明，且时间线有对应失败步骤。 |
| N04 | 超时后的可恢复性 | 超时结束后查看上下文并发送一条只读短指令 | Runtime 回到可用状态；失败轨迹保留，新任务可以正常开始。 |

## 通过标准

- N01/N02 必须证明 SQLite/Trace 在桌面进程重启后可读。
- N03 必须显示具体阶段和错误原因，不能只显示“任务失败”。
- N04 必须证明超时不会污染后续任务状态。
- 本轮只做页面操作和进程启停，不修改代码。
