# Capybara Workbench UI 回归报告（2026-11-14 第六轮：界面控制面）

本轮按既有黑盒测试用例 A-G 检查桌面页面、菜单、运行上下文、项目应用和设置资源入口。测试前已在 `ui-regression-test-cases-2026-11-14.md` 中记录步骤，本轮只点击和观察，没有边测边改代码。

## A：启动、窗口和原生菜单

窗口正常打开，标题、当前项目和本地工作服务可见。文件、视图、工具、帮助四个菜单均能展开，菜单项没有重复渲染。

- 文件菜单：新会话、打开项目、项目文件、导出项目快照均有入口；项目文件和导出项目快照会在主区给出“入口已保留，当前项目暂无可执行内容”的明确反馈。
- 视图菜单：项目侧栏、项目应用、深色外观均可见；这些入口目前属于占位动作，深色外观不会切换主题，只显示入口保留提示。
- 工具菜单：定时与触发、协作任务、进程管理、项目资源、能力演化、本地运行与恢复、Token 用量、设置均可见。协作任务能打开运行上下文；项目资源和设置能打开设置资源模态框；其他未接入动作给出占位提示。
- 帮助菜单：关于概念稿入口可点击，并给出占位提示。

## F：项目应用面板

页面实际显示的标签为“总览”“内容与数据”“资料来源”；当 `marketResearch` 有结果时，“内容与数据”动态显示为“分析结果”。总览和资料来源可以打开，空资料状态有说明。

应用生命周期操作结果如下：

1. 启动应用后显示 `运行中`、本地地址、PID、端口和 `healthy`，并出现打开、停止、重启、更新、展开、收起按钮。
2. 打开应用会在 Electron 内嵌浏览器中加载“清笺”页面，顶部出现“关闭应用视图”，关闭后回到项目应用面板。
3. 点击停止后状态变为停止，按钮恢复为启动应用。
4. 停止后点击重启，页面一度显示“需恢复”，但同时有 PID 和 `healthy`；按钮仍显示“启动应用”和“重启”，需要再次点击启动应用才回到 `运行中`。
5. 启动后展开和收起按钮可以点击，但在未打开嵌入浏览器时没有可见布局差异。

设置模态框显示全局模型、协议、Base URL 和密钥配置状态，密钥输入框为密码类型，不回显明文。点击保存后显示：

## 已确认的新增缺口

### R6-01：应用重启状态没有一次性收敛

重启操作返回了健康 PID，但界面状态为“需恢复”，按钮仍要求再次启动。启动、重启、健康检查和 UI 状态需要统一到同一个实例状态机。

### R6-02：应用标签名称随数据动态变化

同一位置在无市场研究时显示“内容与数据”，有研究结果时显示“分析结果”。这会让测试、用户记忆和会话回放无法依赖稳定的页面名称，应明确这是固定标签还是结果视图。

### R6-03：应用面板与组合研究实例仍可能不是同一个实例

市场研究结果可以发布并打开本地看板，而右侧项目应用面板仍可能显示另一个空白应用实例。手工启动面板应用后状态才同步。需要统一 `applicationId/instanceId/version`，避免一个项目同时出现两个运行状态。

### R6-04：多个菜单动作仍是占位入口

深色外观、能力演化、Token 用量、关于概念稿等按钮可以点击并有提示，但没有对应页面或实际能力。这些入口当前不能算功能验收通过。
