# Capybara Workbench 阶段性 Review 与回归报告（2026-11-14 第十轮）

本轮在上一轮修复之后重新启动 Electron，继续只通过页面和桌面窗口进行黑盒验证。重点是项目应用实例生命周期、嵌入式浏览器宿主、运行上下文和系统设置入口。

## 本轮通过项

### 项目应用实例生命周期

- 进入已有项目应用面板后，点击“启动应用”成功进入“运行中”。页面显示本地地址、PID、端口和 `healthy`。
- 点击“停止”后，页面切换为“已停止”，启动入口恢复，未出现残留的运行中状态。
- 点击“重启”后，页面重新进入“运行中”，并获得新的 PID 和端口；没有复现旧 recovered instance 抢占新实例的问题。
- 在总览、内容与数据、资料来源三个标签间切换，页面可正常显示，未出现前端异常。

### 运行上下文、进程和子智能体

- “查看运行上下文”可以打开右侧运行上下文面板。
- 时间线显示模型阶段、工具名、调用 ID、状态、开始/结束时间、耗时以及失败原因。
- 进程页显示本轮工具进程及其成功/失败状态。
- 子智能体页能明确显示当前会话没有子智能体，而不是空白或报错。
- 候选信息、待审核/冲突、证据/应用收据和项目/会话修订数量均可见。

### 嵌入式应用和项目应用页面

- “打开应用”在 Capybara 内嵌浏览器中打开了本地项目应用，未创建 iframe；主窗口出现“关闭应用视图”入口。
- 嵌入式应用页面可交互。以本地笔记应用为例，页面成功保存一条临时回归笔记，SQLite 计数从 1 则变为 2 则，列表出现新记录。
- 关闭内嵌应用视图后，工作台回到项目应用面板，主页面仍可操作。
- 该临时笔记的删除操作能弹出确认门禁；本轮没有确认删除，测试数据仍保留，见“遗留事项”。

### 系统设置和导航

- “工具 → 设置”可以打开项目设置与资源面板。
- 设置页显示当前模型提供方、模型、协议、Base URL、API Key 已配置状态，密钥不会明文显示。
- 系统提示词字段、动态上下文、Skill 安装入口和已安装资源列表均可见。
- “视图”菜单能打开，项目侧栏可收起并恢复；主区宽度随之变化。
- “工具”菜单能打开并列出定时与触发、协作任务、进程管理、项目资源、能力演化、本地运行与恢复、Token 用量、设置等入口。
- “帮助”菜单能打开并显示“关于概览”入口。

## 本轮发现的缺口

### P1：项目应用的内容页和资料页仍偏展示层

标签可以切换，但“资料来源”页在当前示例应用中只显示项目卡片，没有把本轮研究结果中的来源、证据和引用映射到应用页面；“内容与数据”页也没有展示真实的数据块。运行时轨迹已有证据，应用内容投影还没有闭合。

### P1：应用实例状态与应用内容仍是两条投影链

项目应用面板能够显示独立的 supervisor 实例状态并启动嵌入式应用，但当前示例仍显示“v1 · 空白应用”。研究结果里的应用地址可以打开真实的应用页面，二者之间的版本、内容和 instanceId 关联还不够清晰。

### P2：部分菜单入口仍是概念或占位入口

“视图”中的项目侧栏入口会给出“入口已保留，当前项目暂无可执行内容”一类提示；工具菜单中的能力演化、Token 用量、本地运行与恢复等入口本轮只确认了菜单可见，尚未形成完整的页面工作流。帮助中的关于概览也只确认入口存在。

### P2：缺少有子智能体的真实页面回归

当前研究场景没有产生子智能体，页面可以正确显示“0”，但还没有验证父任务、子任务、子工具调用和合并结果的可见性。

### P2：项目关闭、重开和无效项目清理仍未在本轮重新执行

本轮重启后项目和会话恢复正常，但没有再次执行关闭项目、重新打开项目、删除目录后刷新项目列表的完整链路。

### P2：临时回归数据未删除

为验证应用写入流程，项目应用中新增了标题为“回归临时笔记”的记录。点击删除时应用正确弹出确认对话框；本轮遵守确认门禁，没有确认删除，因此该记录仍在项目应用 SQLite 中。

## 结论

本轮确认了以下闭环已经达到可演示和继续施工的水平：

```text
项目应用面板
  → supervisor 启动 / 停止 / 重启
  → PID、端口、healthy 状态
  → Capybara 内嵌浏览器打开
  → 应用页面可交互
  → 关闭嵌入式视图

运行上下文
  → 时间线
  → 工具进程
  → 候选 / 证据 / receipt
  → 子智能体状态
```

当前仍不能称为全部验收通过。下一阶段优先级应为：

1. 把应用内容、资料来源、证据和版本投影到同一条应用数据链。
2. 统一研究应用地址、supervisor instanceId、应用版本和页面状态。
3. 完成项目关闭/重开/无效项目清理，以及至少一个真实 A2A 子任务回归。
4. 清理或提供明确管理入口处理本轮临时回归笔记。
