## 仍需补齐的缺口

### P1：真实端到端产品链尚未完成

需要在真实 Electron 项目中连续完成并回放：

```text
打开项目 → 配置全局 Key → 聊天
→ 浏览器调研 → 下载研报 → 获取日线
→ 编写并执行 Python → 生成并打开看板
→ 形成带依据、风险和不确定性的待审查建议
→ 重启项目后恢复完整轨迹
```

当前各模块已有能力和自动化覆盖，但这条链仍缺一次统一的桌面验收证据。

### P1：异常路径的页面证据

还需要通过页面验收加载失败、浏览器崩溃、Runtime 断线、工具/Python 超时、下载失败、哈希变化、项目切换中的运行任务，以及子代理部分成功后的父代理合并。

### P1：Trace 从“可见”到“可追踪”

运行上下文已经能看到模型轮次、工具、进程、子代理、候选、证据和收据，但还需要让用户从一个 `turnId / stepId / callId` 点到同一条链上的参数摘要、进程、Receipt、Evidence、Artifact、验证结果和最终回复。

### P2：状态和终态统一

Browser、Application、Market Research、Python、A2A 的状态需要统一映射到 `running / waiting / awaiting_user / reconnecting / succeeded / failed / unknown / needs_verification`，并在 Timeline、项目应用和输入区保持一致。

### P2：历史版本的展示策略

不同 run 的同类产物仍会逐条显示。若产品希望只看当前版本，需要增加按 run/version 的折叠、筛选或“当前版本”视图；这属于展示治理，不应再次用同 ID 去重掩盖历史记录。

### P2：页面可测试性与可访问性

“复核 / 接受 / 拒绝”应补充带 artifactId 的 `aria-label` 或稳定的 `data-testid`，并在卡片上显示精简 ID/版本信息，保证窄侧栏和自动化回归都能准确定位对象。
