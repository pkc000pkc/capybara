# Electron 页面回归计划（Round95）

日期：2026-11-15

本轮目标：验证子智能体异常是否能形成可回放的失败轨迹，以及项目应用停止、打开和后续请求是否能恢复；测试期间不修改代码。

## 用例

| ID | 场景 | 页面操作 | 预期 |
|---|---|---|---|
| C01 | 子智能体失败 | 请求父代理委派子智能体，只读读取确定不存在的文件，失败后不重试 | 页面显示父任务、子任务、子工具失败收据、失败原因、关联 ID 和最终收束状态。 |
| C02 | 失败后恢复 | C01 完成后发送“只回复 OK，不调用工具” | 新请求正常完成，前序失败轨迹仍可回放，不能残留运行中状态。 |
| A01 | 应用打开 | 在项目应用面板打开已发布应用 | 页面显示打开动作结果、应用地址或嵌入视图状态，不能把已停止状态误报为运行中。 |
| A02 | 应用停止/恢复 | 若 A01 启动了托管实例，停止后再次打开；否则观察已停止状态下的打开行为 | 启停状态和打开结果一致；应用异常不能阻塞聊天请求。 |

## 通过标准

- 只通过 Electron 页面发起和观察操作；不使用 shell 代替产品能力。
- C01 必须能区分父任务失败与子工具失败，并保留 `childId`、`callId`、`stepId` 或明确记录缺失字段。
- A01/A02 必须显示真实运行状态、应用地址和失败原因，不用静态卡片推断进程状态。
- 所有用例完成后再统一记录问题，不在本轮测试中修改代码。
