# UI 黑盒回归报告（Round 28）

日期：2026-11-14  
范围：项目应用健康生命周期、内嵌视图关闭和项目切换

## 结论

R28-01 至 R28-05 全部通过。健康应用可以停止并清理运行态信息，重启后重新分配地址、PID 和端口并恢复 `healthy`；应用页面可以在 Electron 内嵌浏览器中打开和关闭；关闭视图不影响托管进程；切换到另一个项目后，旧项目的应用视图没有残留，新项目显示自己的独立应用状态。

本轮验证的是页面行为和页面可见状态，没有把代码调用结果当作验收证据。

## 黑盒证据

### R28-01：停止健康应用

- 初始项目：`qingjian-generated`。
- 页面初始显示 `运行中`、本地地址、PID、动态端口和 `healthy`。
- 点击“停止”后，页面显示 `已停止`、`本地地址待分配`，旧 PID、端口和健康状态不再作为运行状态展示。

判定：通过。

### R28-02：重启健康应用

- 在停止态点击“重启”。
- 页面恢复 `运行中`、有效本地地址和 `healthy`。
- 页面显示新的 PID 和新的动态端口，说明旧实例状态没有直接复用。

判定：通过。

### R28-03：打开内嵌应用

- 点击“打开应用”。
- Electron 主窗口出现内嵌应用页面，页面内容为项目应用的真实页面（清笺本地笔记）。
- 顶部出现“关闭应用视图”和“停止应用”入口。

判定：通过。

### R28-04：关闭内嵌应用视图

- 点击顶部“关闭应用视图”。
- 内嵌浏览器页面消失，项目工作区恢复。
- 右侧项目应用仍显示 `运行中`、原地址和 `healthy`，说明视图状态和托管进程状态已分离。

判定：通过。

### R28-05：切换项目

- 从 `qingjian-generated` 切换到 `ui-regression-clean-2026-11-14`。
- 顶部项目名、工作区内容和右侧应用面板全部切换到新项目。
- 新项目显示自己的 `v1 · 空白应用` 和 `已停止` 状态，没有带入旧项目的地址、PID、端口、应用页面或运行态。
- 旧项目实例是否继续在后台运行不由本用例判定；本轮确认的是视图、页面状态和项目上下文没有错误串入。

判定：通过。

## 本轮发现与限制

- 项目切换时，页面层已完成视图和状态隔离；仍需补一条专门的后台进程清理策略验收，明确旧项目切换后实例是保持运行、自动停止还是交由用户管理。
- 应用启动/停止/重启的收据尚未在“运行上下文”中按 `turnId / stepId / callId` 独立回放，本轮只验证了项目应用面板的最终状态。
- 项目应用侧的更新成功与失败回滚已在 Round 27 验证；本轮补齐了健康版本重启和打开/关闭视图路径。

## 阶段判断

项目应用基础生命周期和 Electron 内嵌浏览器的页面闭环已达到可用水平，但产品化验收仍未通过。下一步重点转向运行上下文的 application receipt 回放、后台实例策略、菜单/资源治理和真实业务场景回归。
