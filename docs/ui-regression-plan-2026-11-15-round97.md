# UI 页面回归测试计划（Round 97）

## 目标

验证 RuntimeLoop 已有的 continuation 上限是否通过 Electron 页面自动生效，并确认无工具模型循环最终会显示明确失败阶段和错误码。

## 测试环境

- Electron 桌面应用（当前构建）
- 项目：`qingjian-generated`
- 测试方式：仅通过页面控件和聊天输入

## 测试用例

### R97-01：无工具模型循环自动收束

创建新会话，输入：

> 请委派一个子智能体读取项目根目录下确定不存在的 `__capybara_child_missing_round97_retry__.txt`；如果第一次读取失败，父任务必须使用完全相同的 delegate_task 请求再重试一次；第二次失败后立即停止，不要再重试，不要修改任何文件。最终回复必须保留真实收据。

预期：

1. 页面显示子任务失败及其证据。
2. 如果模型继续输出无工具的“继续模型循环”，达到运行时 continuation 上限后自动终止。
3. 页面进入失败终态，显示具体阶段和错误码（例如 `MODEL_CONTINUATION_LIMIT`），无需点击“停止本轮”。
4. 已有工具调用、artifact、evidence 和最后可验证事实仍可见。

### R97-02：自动失败后的恢复

输入：

> 只回复 OK，不调用工具。

预期：显示 `OK`，且本轮工具调用数为 0。

## 通过标准

- R97-01 在 continuation 上限处自动结束并显示明确失败原因。
- R97-02 可以正常恢复。
- 若自动终止不生效，再修复 RuntimeLoop 并重建后重复本轮。
