# UI 黑盒回归计划（Round 44）

日期：2026-11-14  
范围：资源来源标签与项目资源错误文案修复后的页面回归

## 目标

确认资源目录直接表达项目资源与系统回退来源，且 Skill/插件操作失败时只显示面向用户的资源错误，不泄漏 Electron IPC 方法包装。

## 用例

| 编号 | 页面操作 | 预期 |
| --- | --- | --- |
| R44-01 | 在 `qingjian-generated` 打开设置并查看已安装资源 | 每行显示“来源：项目资源”或“来源：系统回退”，路径、类型和 revision 仍可见 |
| R44-02 | 切换到空项目并查看设置资源 | 系统回退与项目资源标签准确，不能把来源留给用户猜测 |
| R44-03 | 提交不存在的插件目录 | 错误显示“工具插件安装失败：…”及具体原因，不出现 `Error invoking remote method` |
| R44-04 | 在原项目确认已安装 `openai-docs` 与 000682 应用 | Skill 仍在原项目，研究应用和会话状态不受影响 |
| R44-05 | 关闭并重新打开设置 | 来源标签、目录 revision 和当前错误状态正确恢复；旧错误不伪装成成功 |

## 判定规则

- 必须使用新构建启动的 Electron 页面验证。
- 先完成全部用例，再决定是否继续修复。
- 资源来源以页面显式标签为准，不以路径推断作为通过证据。
