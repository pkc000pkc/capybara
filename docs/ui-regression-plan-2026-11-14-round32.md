# UI 黑盒回归计划（Round 32）

日期：2026-11-14  
范围：上一轮未闭环的菜单、资源治理、运行上下文细节和异常分支

## 目标

在不修改实现的前提下，补齐上一轮阶段 Review 中仍未验证的页面入口和高风险状态。先完整执行本轮所有用例并记录结果，再决定是否修复；不得在本轮点击过程中修改代码。

## 用例

| 编号 | 页面操作 | 预期 |
| --- | --- | --- |
| R32-01 | 打开文件、视图、工具、帮助四个顶部菜单，逐项检查并点击未验证入口 | 每个入口唯一；有实际页面、对话框或明确状态反馈，不得静默无响应或重复 |
| R32-02 | 切换项目侧栏、项目应用、深色外观和窗口布局 | 主区不被遮挡，切换后项目、会话和输入状态保持一致 |
| R32-03 | 搜索项目名、会话首句和不存在内容，再清空搜索 | 命中层级清晰；无匹配有空状态；清空后列表恢复 |
| R32-04 | 打开工具/Skill/设置资源视图 | 项目级与系统级资源来源、优先级和去重关系可理解；不出现重复资源 |
| R32-05 | 打开运行上下文的时间线、进程、子智能体、证据治理 | 每个页签可切换；当前会话数据一致；空状态和计数可解释 |
| R32-06 | 展开一条模型阶段摘要和一条工具/证据收据 | 显示安全阶段摘要、参数摘要、结果、失败原因和关联键，不泄漏原始思维文本 |
| R32-07 | 在当前页面制造或查看已有工具失败/非零退出记录 | 页面显示失败阶段、耗时、退出码和原因，最终回复不得把失败说成成功 |
| R32-08 | 切换会话与项目后回到原会话 | 消息、运行轨迹、应用状态和输入草稿不串项目/会话 |
| R32-09 | 关闭并重新打开运行上下文和项目应用 | SQLite/trace 回放保留消息、步骤、证据、应用版本和生命周期收据 |
| R32-10 | 检查应用内容与数据、资料来源、运行差异和展开/收起 | 各页有真实内容或明确空状态；展开后不遮挡控制区 |

## 判定规则

- 只以页面实际可见反馈判定，不用源码、缓存或自动化测试替代页面验收。
- “有按钮但点击无反馈”记为失败；“明确说明暂不可用/无数据”记为通过但记录产品边界。
- 第一轮全部用例完成后，才允许集中修复局部逻辑缺陷。
- 若发现需要基础框架或协议改变的问题，只记录为缺口，不在本轮直接改动。
