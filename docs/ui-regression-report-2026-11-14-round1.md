# Capybara Workbench 黑盒回归报告（第一轮）

日期：2026-11-14  
方式：启动 `npm run desktop:start --workspace=apps/workbench` 后，通过桌面窗口截图、点击、输入和键盘操作验收。第一轮没有修改代码。

## 结论

主工作台可以启动，项目和历史会话可以加载，运行上下文、时间线详情、设置界面、项目应用启动和嵌入式浏览器均能打开。嵌入的清笺应用可以保存和搜索一条记录。

首轮没有达到全功能可验收状态，主要阻塞点是：API Key 返回 401 后会话仍保持“运行中”，停止本轮没有解除；新会话按钮没有明显创建并选中新会话；项目关闭入口点击后只显示提示，没有关闭项目；嵌入浏览器打开后缺少可见的关闭/返回控制，导致应用生命周期按钮无法继续点击；部分工具菜单项点击没有可见页面反馈。

## 缺陷清单

### R1-01 新会话点击没有形成可见的新会话

- 重现：在 `coding` 项目中点击左侧“新会话”。
- 实际：主区仍显示原会话标题和内容，列表没有明显新增并选中的会话。
- 影响：无法确认会话隔离和新会话入口可用。
- 第二轮候选修复：前端创建/选择后的状态刷新和列表渲染。

### R1-02 模型 401 后运行态卡住

- 重现：在会话输入“请回复……不要调用工具”，用 Ctrl+Enter 发送。
- 实际：消息区显示 `LLM request failed (401 Unauthorized)`，顶部仍显示“运行中/正在等待模型输出”，点击“停止本轮”后仍未恢复空闲，发送按钮保持不可用。
- 影响：一次模型配置错误会阻塞当前会话后续操作。
- 处理边界：涉及 RuntimeLoop/运行状态清理，第一轮不在前端回归中修改，需单独作为运行时缺陷处理。

### R1-03 项目关闭入口未关闭项目

- 重现：项目行右侧箭头/关闭入口。
- 实际：显示“关闭项目”提示，但点击后项目仍在列表，当前项目仍可用。
- 第二轮候选修复：检查按钮事件绑定、项目列表刷新和当前项目清理。

### R1-04 嵌入式浏览器缺少可见关闭/返回控制

- 重现：启动 `capybara` 应用并点击“打开应用”。
- 实际：WebContentsView 正常显示清笺页面，保存和搜索有效；页面覆盖右侧项目应用面板，项目应用的关闭/停止等控制不可见，`Escape` 和“视图 > 项目应用”没有关闭浏览器。
- 第二轮候选修复：提供明确的浏览器关闭/返回入口，并恢复项目应用控制可达性。

### R1-05 工具菜单存在无可见反馈的入口

- 重现：打开“工具”菜单，依次点击进程管理、能力演化、本地执行与恢复、Token 用量等入口。
- 实际：菜单关闭或停留在当前页面，没有新页面、弹层、状态变化或错误说明。
- 第二轮候选修复：如果这些入口已有页面，补齐导航；如果仍未提供页面，至少显示明确的空状态/未配置状态。

### R1-06 设置操作缺少反馈

- 重现：设置中点击保存模型设置、Skill 预览/安装、工具插件预览。
- 实际：按钮可点击，但没有成功、失败、缺少输入或正在处理的可见反馈。
- 第二轮候选修复：补充按钮状态、校验提示和结果反馈；不改变配置协议。

## 已通过的关键证据

- 目录选择器能打开当前目录并取消，主页面显示取消反馈。
- 运行上下文可以查看时间线、轮次、工具耗时、工具详情和调用参数。
- 项目应用能从停止变为运行中并显示 PID/端口/健康状态。
- 内嵌浏览器不是 iframe，清笺页面可见；创建记录后显示“已保存《回归测试》”，搜索过滤能显示该记录。
- 401 错误被原样归入失败消息并展示具体原因，没有伪装成成功。
