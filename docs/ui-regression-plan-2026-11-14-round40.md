# UI 黑盒回归计划（Round 40）

日期：2026-11-14  
范围：托管后端自动启动修复后的设置与资源页面

## 目标

确认标准 Electron 启动会自动带起本地后端，设置页面的项目变量/资源目录可正常读取；非法 Skill/插件请求不再显示底层 `fetch failed`，而是返回资源级错误，同时不影响当前会话和运行上下文。

## 用例

| 编号 | 页面操作 | 预期 |
| --- | --- | --- |
| R40-01 | 启动 Electron 后用 `Ctrl+Comma` 打开设置 | 全局配置、项目变量、资源目录和 revision 均正常显示，不出现资源读取失败 |
| R40-02 | 输入不存在的 Skill 仓库/路径并点击预览 | 页面显示仓库/路径或远程资源的具体失败原因，不出现 `capybara:project-api` 或 `fetch failed` |
| R40-03 | 输入不存在的插件目录并点击预览并安装 | 页面显示目录/manifest/项目边界的具体失败原因，不出现安装成功 |
| R40-04 | 关闭并重开设置 | 全局配置、变量、资源列表和 revision 保持；失败提示仅代表本次请求 |
| R40-05 | 返回运行上下文和项目应用 | 会话轨迹、应用实例、布局和证据治理不受资源操作影响 |

## 判定规则

- 只用 Electron 页面可见文字、按钮和状态判定。
- 后端启动成功必须由页面结果和已验证的本地服务状态共同支持。
- 本轮不修改代码；发现问题时完成整轮并记录，再进入下一轮修复。
