## 本轮确认的关键缺口

### P0：超时证据协议不闭环

同一条用户请求的最终回复同时包含两种互相冲突的结论：

- “已按当前超时策略验证了超时行为”；
- “没有拿到可用工具收据，不能断言 timeout 是否触发、进程是否收束”。

运行上下文里能看到多次 `run_command`，但页面没有稳定呈现 `timed_out`、`exit_code`、`signal`、`duration` 和子进程收束状态的统一收据。这个缺口会直接破坏“结果可验证、错误可定位”的目标，优先级高于普通 UI 占位入口。

### P1：非零退出可以观测，但工具允许跨出工作区

非零退出闭环本身成功，页面能准确显示退出码和失败原因；但 Agent 在临时目录写脚本并从项目外执行，页面只作为说明展示，没有清晰的能力门禁状态。需要明确“临时执行目录”和“项目工作区”的边界，以及跨工作区执行是否必须显式授权。

### P1：子智能体结果缺少父级独立证据副本

页面能显示 childId、子代理时间线和合并结果，但最终不确定性里明确写出父代理没有收到独立工具收据副本。父任务可以看到子代理自述，不能独立校验子代理工具结果，A2A 证据链仍不完整。

### P2：应用面板在页面回归中不稳定

AX 树能列出项目应用控制按钮，但页面截图多次只显示空白右侧区域，导致启动、停止、重启、关闭内嵌视图无法形成稳定的黑盒证据。需要先修复面板可见性/滚动定位，再继续应用生命周期验收。

## 已验证的闭环能力

- 工具调用会显示工具名、callId、状态、时间和耗时。
- 文件读取结果会进入聊天回复和运行上下文，且保留不确定性说明。
- 非零退出会保留 stdout、stderr、退出码、是否超时和失败原因。
- 子智能体会显示独立的子代理阶段、子代理工具和父级合并结果。
- 会话切换后运行上下文、修订计数和空状态会随新会话重置。

## 下一轮优先顺序

1. 统一 `run_command` 超时/退出收据 schema，禁止最终回复在缺少证据时宣称已验证。
2. 检查超时后的子进程收束，至少在页面显示 `timed_out`、`exit_code`、`signal`、`duration` 和残留进程检查结果。
3. 将子代理工具收据以父级可引用的证据包形式落盘，而不是只保留子代理自述。
4. 修复项目应用面板可见性和滚动定位，再补启动、停止、重启、更新失败和回滚。
5. 处理项目文件/导出快照及工具菜单占位入口，完成产品层闭环。

## 结论

Round 18 证明了读取文件、非零退出、子智能体和会话切换的页面链路已经具备可观测性；超时证据链和应用生命周期仍未达到验收标准，其中超时场景的自相矛盾回复属于 P0 级闭环缺口。当前状态应判定为“运行轨迹可见，但错误证据协议和应用生命周期仍需修复”。
