# Capybara V2 页面回归计划（Round62）

## 目的

验证 Round61 暴露的项目/会话切换后项目应用状态回落问题的修复，并复测搜索、历史会话、研究结果和基础发送链路。本轮使用重新构建并通过标准 `npm run desktop:start` 启动的 Electron 页面；先完成全部页面操作，再决定是否继续修复。

## 用例

| 编号 | 页面动作 | 通过标准 |
|---|---|---|
| R62-01 | 启动后等待当前项目恢复，检查 000682 研究结果、发布地址和应用状态 | 研究结果、看板地址、已发布状态自动恢复，不显示空白应用。 |
| R62-02 | 点击当前项目行，再检查项目应用 | 同一项目重新选择后，研究结果和已发布应用状态保持，不回落为空白应用。 |
| R62-03 | 在当前项目切换历史会话，再返回研究会话 | 消息和运行轨迹按会话恢复，项目应用仍保持正确的项目级发布状态。 |
| R62-04 | 切换到另一个有效项目，再切回当前项目 | 另一项目不显示当前项目研究结果；切回后 000682 研究结果和应用状态恢复。 |
| R62-05 | 发送 `hi`，检查唯一用户消息、助手回复和输入清空 | 发送链路不重复、不阻塞，运行状态与结果可见。 |

## 记录要求

- 只通过页面点击、键盘和标准 Electron 窗口操作。
- 记录每次项目/会话切换前后的应用版本、发布状态、地址和研究结果。
- 本轮不修改代码、不安装资源、不删除项目或会话。
