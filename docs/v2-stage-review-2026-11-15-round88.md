# V2 阶段审查（Round88）

日期：2026-11-15

## 阶段判断

核心展示闭环已经从“脚本级可产生 trace”推进到“Electron 当前会话实时可见，并且项目切换后可回放”。这意味着运行时事件、聊天消息、工具结果和运行上下文已经形成一条可观察链，达到继续做故障态和冷启动验收的阶段。

## 已有页面证据

- 一次真实只读任务产生 2 次工具调用、4 个步骤。
- 运行中能看到“正在等待模型输出”，并能看到模型阶段和两个工具步骤。
- 完成后聊天区显示真实目录和 README 内容，运行上下文显示时间线 4、进程 2、证据引用 4。
- 切换到另一个项目再切回后，原会话仍保留 1 次请求、用户消息、工具结果和运行轨迹。
- 项目应用、内嵌看板、来源/产物治理、布局控制和设置面板已在上一轮通过。

## 当前缺口

- Electron 进程冷启动后的 SQLite/Trace 回放尚未验证。
- 超时、权限拒绝、模型失败、应用启动失败的错误态尚未形成页面证据。
- 子智能体非空运行态及父子任务合并链尚未形成页面证据。
- 具体候选和证据条目的详情尚未验证是否能回到 `turnId / stepId / callId`。
- 设置面板关闭后的回退状态尚未单独验证。

## 下一阶段门槛

先完成冷启动回放，再执行一个明确会超时的只读脚本任务。验收需同时覆盖成功和失败两条路径，并确认时间线、进程、证据、最终状态和关联 ID 在切换项目与重启 Electron 后保持一致。
