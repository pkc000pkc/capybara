# UI 回归测试计划：Round68

- 日期：2026-11-15
- 目标：针对阶段 Review 中尚未闭环的交互式浏览器与应用异常状态，确认页面是否提供可执行入口、状态反馈和可回放证据。
- 约束：只通过 Electron 页面和控件操作；本轮测试过程中不修改代码；先完成全部用例，再沉淀报告。

## 测试用例

| ID | 场景 | 操作步骤 | 预期 |
|---|---|---|---|
| R68-01 | 浏览器网关入口 | 在项目应用面板点击“浏览器网关”状态入口，记录是否出现可操作的浏览器页面、地址和状态 | 页面应明确显示浏览器会话/页面入口，或给出明确受控状态 |
| R68-02 | 浏览器导航能力 | 通过页面可见入口尝试打开一个公共网页，观察是否有地址、导航、前进后退或刷新控件 | 能看到可验证的导航状态与页面内容，不能只有固定摘要 |
| R68-03 | 浏览器交互能力 | 在可见浏览器页面中寻找点击、输入、选择、等待等用户可观察入口 | 交互动作应有状态、结果和失败原因 |
| R68-04 | 浏览器下载与证据 | 对公开下载链接执行下载或打开动作，检查文件、来源、时间和证据是否可见 | 下载结果可追溯，失败也有明确阶段和原因 |
| R68-05 | 浏览器状态回放 | 关闭并重新打开运行上下文或切换会话后，检查浏览器动作、页面状态和证据是否保留 | 能恢复完整浏览器轨迹，不能只剩最终摘要 |
| R68-06 | 应用异常入口 | 在项目应用面板检查停止、重启、更新、回滚、失败状态下的按钮与反馈 | 状态和动作一致，异常状态有恢复或解释入口 |
| R68-07 | 页面与运行上下文一致性 | 打开/关闭应用视图、运行上下文和项目应用面板，检查页面状态、收据和地址是否一致 | 不出现旧地址、空白视图或不可解释的状态组合 |

## 记录要求

记录每个用例的可见入口、实际结果、是否满足预期和对应缺口。若确认是产品能力缺失而不是页面阻塞，完成整轮后写入阶段 Review，不在测试中修改代码。
