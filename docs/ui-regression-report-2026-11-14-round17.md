## 本轮修复确认

`startNewSession` 的短窗口从 750ms 调整为 2000ms，并继续保留创建中单飞保护。新构建页面复测后，连续两个键盘事件只创建一条新会话，Round 16 的 P1 缺陷已关闭。

## 仍然存在的缺口

### P1：项目资源读取告警与资源展示不一致

干净目录的设置面板同时出现“项目提示词变量、项目资源目录读取失败”和系统资源列表。需要明确项目资源初始化/回退顺序，并把告警限定在真正失败的范围。

### P1：上下文中仍保留历史超限失败记录

新消息已经可以完成，但运行上下文时间线仍能看到历史 `CONTEXT_WINDOW_EXCEEDED` 失败。回放是正确的，但产品层需要区分“历史失败”与“当前运行状态”，避免用户误判当前修复没有生效。

### P2：项目文件与导出快照仍为占位入口

当前页面有明确状态提示，但没有文件视图、导出产物或路径收据，尚未形成可验收的产品闭环。

### P2：定时、能力演化、Token 用量仍为占位入口

入口可达，功能面尚未展开。需要明确是真实空状态、未配置状态还是尚未接入状态。

### P2：项目应用面板关闭/重开缺少稳定的页面证据

AX 树能看到关闭按钮，截图状态却受主工作区滚动影响。下一轮应先回到固定页面布局，再验证关闭与重新打开，避免只依赖 AX 存在性。

## 继续回归前必须覆盖

1. 读取文件工具的真实调用、结果和证据回放。
2. Python 脚本成功、非零退出和超时。
3. 浏览器工具失败与重试限制。
4. 真实子智能体及父任务合并。
5. 断线重连后时间线恢复。
6. 项目应用启动、停止、重启、更新失败和回滚。

## 结论

新会话重复创建缺陷已修复并通过页面复测；单次发送、运行上下文、项目切换和资源展示均可用。项目文件/导出、三个工具入口、资源告警、应用面板关闭证据及高风险运行场景仍未达到全量验收标准，因此当前阶段应判定为“核心工作台可用，产品闭环尚未完成”。
