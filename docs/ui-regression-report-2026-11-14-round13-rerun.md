## 已闭合的缺口

1. 会话列表在重启后丢失可识别标题。原因是数据库名称仍为“新会话”，列表没有从压缩快照中的首条用户消息派生显示标题。现在列表查询对默认名称执行快照派生，保留数据库兼容性。
2. 项目资源读取告警。系统级 `tools/files` 和 `skills/project-files` 之前只在源码树存在，桌面用户目录没有稳定的系统资源副本。启动时现在会把缺失的系统资源复制到用户级 `.capybara`，并由项目资源读取接口正常返回。
3. 项目应用重启后被显示为空白 v1。运行时 manifest 实际仍在项目 `.capybara/applications` 中，但前端只根据市场研究缓存渲染项目应用卡片。现在前端以 Electron 返回的 `applicationRuntime.manifest` 作为兜底，显示真实版本、地址、运行状态和进程信息。

## 仍然存在的产品缺口

### P1：市场研究看板与一般项目应用的状态模型仍未完全统一

本轮确认的是项目 manifest 和应用进程恢复；历史 H05 生成的 `000682 行情看板` 研究结果仍主要通过会话/市场研究缓存表达，而一般项目应用通过 manifest 表达。两者可以分别恢复，但还没有一个统一的“当前应用版本 + 研究证据 + 来源资料”实体模型。下一步应让应用版本、研究产物、证据和会话引用使用同一个持久化索引，避免只恢复应用壳或只恢复研究结果。

### P1：应用运行状态与浏览器视图状态是两套状态

应用进程可以显示 `running/healthy`，嵌入浏览器也可以单独打开或关闭。重启、进程异常退出、浏览器视图关闭后的状态恢复还没有完整的自动化验收矩阵，尤其是“进程仍在、视图已关闭”和“进程已死、旧地址失效”两种情况。

### P1：侧栏折叠和搜索层级语义需要补齐

视图菜单的“项目侧栏”入口有反馈，但“隐藏项目与会话列表、再恢复”的页面语义还没有稳定证据。搜索命中项目级文本时会保留该项目下全部会话；需要产品上明确这是项目聚合搜索，还是只显示命中的会话。

### P1：工具/Skill 的系统回退需要增加可见来源标识

当前设置能看到工具和 Skill 已安装，但项目优先、系统回退、同名覆盖关系没有在页面中清晰表达；`capybara-system` harness 仍出现重复项，说明目录合并或展示去重还需要进一步收敛。

### P2：运行上下文仍需扩大黑盒覆盖

上一轮已确认时间线、工具进程、子智能体空状态、证据和失败原因可见。本轮没有重新执行以下高风险场景：工具超时、脚本进程失败、子智能体真实委派、断线重连后完整轨迹回放。它们仍是“可见、可定位、可回放”目标的剩余验收项。
