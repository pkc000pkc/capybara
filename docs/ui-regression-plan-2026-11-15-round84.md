# Electron 页面回归计划（Round84）

日期：2026-11-15

本轮目标：验证遗留研究结果是否已被项目级 Artifact Index 归一化，并验证产物治理动作在页面上可见、可持久化、不会跨项目泄漏。

## 用例

| ID | 场景 | 操作 | 预期 |
|---|---|---|---|
| H01 | 遗留产物归一化 | 打开 qingjian-generated 项目应用，进入“资料来源”并定位产物区 | 研究结果中的遗留产物出现在项目产物列表中，带有明确状态；页面不报 Bad Request |
| H02 | 产物接受 | 对一个已归一化的 research-report 产物点击“接受” | 页面直接出现 `role=status` 审核反馈，状态变为 accepted，按钮状态与返回结果一致 |
| H03 | 状态持久化 | 切换到另一个项目，再切回 qingjian-generated，重新打开“资料来源” | accepted 状态仍然存在；其他项目不显示 qingjian 的治理反馈 |
| H04 | 无文件产物复核 | 对缺少项目相对文件路径的产物点击“复核” | 页面显示明确的文件路径/证据原因，不出现泛化的 400 或静默失败 |

## 通过标准

- H01 必须能在页面看到归一化产物和状态。
- H02 必须有即时可见的审核结果，且状态更新不依赖刷新。
- H03 必须证明治理状态写入项目级存储并在切换后恢复。
- H04 必须保留后端可解释原因，不能只显示通用错误。
- 页面操作期间不修改代码；完成后写入 `docs/ui-regression-report-2026-11-15-round84.md`。
