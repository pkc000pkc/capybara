# Capybara V2 页面回归计划（Round60）

## 目的

验证 Round59 发现的菜单开关缺陷修复，并复查相关页面控制不受影响。本轮只通过新构建的标准 Electron 页面操作，不修改代码。

## 用例

| 编号 | 页面动作 | 通过标准 |
|---|---|---|
| R60-01 | 通过视图菜单反复点击“项目应用”：打开→关闭→再次打开 | 菜单动作与工作区按钮一致，每次都有可见开关变化，项目研究内容不丢失。 |
| R60-02 | 逐项执行工具菜单入口并记录其实际路由：定时与触发、协作任务、进程管理、项目资源、能力演化、本地运行与恢复、Token 用量、设置 | 每个入口都有可观察页面或明确状态；确认入口路由是否重复、静默或显示错误。 |
| R60-03 | 打开项目应用，执行展开、收起、打开应用、关闭嵌入视图 | 布局提示与实际视图一致，嵌入看板可打开和关闭，项目应用面板仍可继续使用。 |
| R60-04 | 切换深色外观后恢复浅色，折叠并恢复项目侧栏，打开/关闭关于窗口和设置 | 主题、侧栏、模态窗口状态可恢复；设置页仍显示全局密钥与系统回退资源。 |

## 记录要求

- 使用标准 `npm run desktop:start` 启动后的窗口。
- 每次菜单动作后重新读取页面状态，记录最终可见文本和状态。
- 本轮不安装外部 Skill、插件或修改配置，只观察入口和页面表达。
- 完整记录后再决定是否需要下一次修复轮。
