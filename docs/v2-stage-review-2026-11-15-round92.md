# V2 阶段性工作审查（Round92）

日期：2026-11-15

## 本轮结论

子智能体闭环已通过页面验收。V2 当前不仅能显示普通工具调用和失败收据，也能显示父层委派、子代理模型阶段、子代理工具调用、结果 artifact、父代理二次读取和最终合并。这使“可观察、可验证、可回放”的目标在 A2A 场景中成立。

## 当前已形成的闭环

```text
父任务
  ↓ delegate_task
childId
  ↓ 子代理模型阶段
子代理工具调用（callId / stepId）
  ↓ runtime receipt + result artifact
父代理读取和交叉核验
  ↓
父任务最终回复与证据说明
```

## 新确认的能力

- 子代理只调用被授权的 `list_files`，未触发写工具。
- 父代理保留子任务 `childId`、父层 `callId`、子层 `callId`、`stepId`、receipt、candidate ID 和 artifact ID。
- 父代理可以通过 `read_runtime_artifact` 对子任务结果进行二次核验，而不是直接把子代理文本当事实。
- 页面执行过程能把父层委派和子代理步骤放在同一条时间线上。

## 新暴露的缺口

### 1. childId 展示口径不统一

工具返回的是 `child:...`，子代理报告使用 `sessionId:child:...`。当前通过内容判断二者对应，但系统应定义 canonical childId、sessionId 和 display label 的关系，避免后续回放筛选出现重复实体。

### 2. 父子事件关联仍偏文本化

最终回复中已经列出各个 ID，但运行上下文还没有给出按 `parentTurnId → childId → childTurnId → callId → artifactId` 的结构化筛选视图。审查者仍需要从时间线和回复文本中手工拼接关系。

### 3. 子代理的失败和权限分支未验收

本轮只覆盖了成功的只读子任务；子代理工具失败、子代理超时、父代理取消、子代理尝试越权写操作仍未形成页面证据。

## 阶段判断

主链路和 A2A 成功链路已达到可演示、可继续验收的水平。当前阶段的主要工作已从“有没有运行闭环”转为“故障态、ID 规范和复杂回放是否足够可审计”。下一优先级是统一 ID 模型，并补一轮子代理失败/权限拒绝场景；随后再处理应用启动失败和重复产物的回放聚合。
