# UI 黑盒回归计划（Round 45）

日期：2026-11-14  
范围：空项目应用状态宿主修复后的 Electron 回归

## 目标

确认没有应用定义的项目被当作正常空状态处理，不再触发“没有 start command”的宿主错误；已有项目应用仍按原状态显示。

## 用例

| 编号 | 页面操作 | 预期 |
| --- | --- | --- |
| R45-01 | 新构建启动后观察空项目项目应用面板 | 显示“空白应用 / 尚未启动”，不出现运行错误或应用状态异常 |
| R45-02 | 切换到 `qingjian-generated` | 000682 应用、发布内容、研究结果和托管实例状态保持 |
| R45-03 | 再切回空项目并打开设置 | 空项目设置、资源来源和会话正常；应用状态仍为空状态 |
| R45-04 | 关闭并重新打开项目应用面板 | 空项目面板可重开，不产生新的启动/状态错误 |
| R45-05 | 关闭并重新打开运行上下文 | Runtime 与会话轨迹正常，项目切换没有串状态 |

## 判定规则

- 必须使用包含宿主修复的新构建 Electron。
- 页面状态和宿主启动日志共同判定；空项目不能以异常方式实现“无应用”。
- 先完成整轮测试，再决定是否继续修复。
