# Capybara V2 页面回归计划（Round64）

## 目的

覆盖 Round63 之后仍需确认的页面入口：文件、视图、工具、帮助菜单的全部可见项，设置入口，项目应用生命周期控制，以及项目关闭/重开。每个入口都记录点击后的可见反馈、状态变化或明确的空状态，区分真实功能、受控占位和无响应。

## 用例

| 编号 | 页面动作 | 通过标准 |
|---|---|---|
| R64-01 | 打开文件菜单，逐项检查新会话、打开本地项目、关闭项目、导出项目快照等入口 | 每个入口有可观察动作；会取消的目录选择不改变当前项目；菜单能正常关闭。 |
| R64-02 | 打开视图菜单，检查运行上下文、项目应用、侧栏、主题等入口 | 每个入口有可见的面板、布局或主题变化，重复点击能恢复。 |
| R64-03 | 打开工具菜单，检查协作任务、进程管理、本地运行与恢复、项目资源、项目设置、项目文件、定时与触发、能力演化、Token 用量 | 每个入口打开对应页面、运行上下文或明确空状态；不存在无响应点击。 |
| R64-04 | 打开帮助菜单，检查关于概念稿和关闭行为 | 关于弹窗显示标题、说明和关闭按钮；菜单可恢复。 |
| R64-05 | 在已发布项目应用中检查总览、内容与数据、资料来源、打开应用、展开、收起、关闭应用视图和查看运行差异 | 页签和按钮有稳定反馈；实例状态、发布状态、视图状态和差异入口一致。 |
| R64-06 | 打开设置，检查全局模型配置、密钥已配置状态、资源目录和关闭/重开 | 设置可见且不回显密钥；关闭后返回工作区，重新打开内容保持。 |
| R64-07 | 通过项目菜单关闭当前项目，再从剩余项目切换回研究项目 | 当前项目从工作区消失且会话不串入；重新打开后会话和项目应用按持久化状态恢复。 |
| R64-08 | 搜索不存在的项目/会话并清空搜索 | 过滤结果为空时有明确反馈；清空后项目和会话列表恢复。 |

## 记录要求

- 使用最新 `apps/workbench/out` 构建并通过标准 `npm run desktop:start` 启动 Electron。
- 每次点击前记录目标入口和预期，点击后读取最新页面状态，不用代码结果替代页面证据。
- 本轮只做页面验证；完成完整用例并写报告后，再决定是否修复发现的问题。
