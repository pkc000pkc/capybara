# UI 黑盒回归报告（Round 37）

日期：2026-11-14  
范围：应用布局反馈修复后的项目应用页面

## 结论

本轮未通过。行情看板可以从项目应用面板打开，并且关闭后再次打开仍保持侧栏布局；但页面同时暴露出运行状态语义不一致：右侧项目应用面板显示“已停止”，底部“本地应用运行”仍显示“运行中”。由于展开/收起按钮只在 `applicationInstance.status === "running"` 时渲染，本轮无法在页面上看到并验证这两个控制项。

测试期间没有修改代码。

## 黑盒证据

### R37-01：运行实例、未打开内嵌视图时点击“展开”

- 项目应用面板显示 `已停止`、持久化看板地址和 `布局：侧栏`。
- 页面只显示“打开应用”，没有显示“展开”按钮。
- 同一页面下方的“本地应用运行”区域却显示 `运行中`，说明发布内容或宿主状态被当成了运行实例状态。

判定：未通过。运行态分轴不一致，布局控制被错误地隐藏，无法形成可验证的展开操作。

### R37-02：点击“收起”

- 因 R37-01 中没有渲染“展开/收起”控制，无法进入可重复的点击路径。

判定：未复测。缺少稳定的页面入口，不代表收起逻辑本身通过。

### R37-03：打开内嵌应用并同步布局状态

- 点击“打开应用”成功打开 Electron 内嵌的 `000682` 行情看板。

- 关闭内嵌视图后再次打开，页面仍显示 `布局：侧栏`，侧栏布局状态被保留。

判定：看板打开/关闭和侧栏状态保留通过；展开/收起同步未通过。

### R37-04：面板、上下文和会话边界

- 关闭内嵌视图后，项目、会话、000682 研究结果、证据和产物仍属于 `qingjian-generated`，没有观察到项目串线。
- 本轮没有形成“切换运行上下文页签后再返回”的新页面证据，Round36 的上下文恢复证据仍然有效但不计入本轮。

判定：项目和会话隔离未见回归；跨入口布局状态的完整回放未通过本轮独立验收。

## 新增缺口

1. **运行实例、已发布内容和嵌入视图使用了不同状态源**：项目应用面板显示 `已停止`，底部运行摘要显示 `运行中`，打开看板又能成功。这让用户无法判断当前到底是在启动实例、读取发布产物，还是打开一个已存在的本地页面。
2. **布局控制和状态条件耦合错误**：展开/收起只绑定到实时运行实例，发布内容可以打开但没有布局控制，导致功能在常见的“已发布但实例状态未恢复”场景下消失。
3. **嵌入视图覆盖项目应用控制区**：打开看板后只能通过顶栏“关闭应用视图”返回，布局调整不能在同一上下文中完成。

## 下一轮建议

- 先定义并在页面上分别呈现“发布内容状态”“托管实例状态”“嵌入视图状态”，再决定按钮文案和可用条件。
- 布局状态应由宿主视图状态驱动，不能只由 `applicationInstance.status` 决定；即使实例状态未恢复，也要显示当前布局和可用的视图控制。
- 增加可从项目应用面板直接切换侧栏/展开的入口，并在布局变化后显示稳定的文字或尺寸反馈。
