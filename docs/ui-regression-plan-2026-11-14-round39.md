# UI 黑盒回归计划（Round 39）

日期：2026-11-14  
范围：设置、资源校验和项目/系统资源展示

## 目标

验证设置页面在真实项目中可达、可关闭、可重开，并对非法 Skill/插件路径给出可见校验；同时确认页面能展示资源目录来源和 revision，不把失败操作误报为安装成功。

## 用例

| 编号 | 页面操作 | 预期 |
| --- | --- | --- |
| R39-01 | 用 `Ctrl+Comma` 打开设置 | 页面显示模型配置、全局密钥状态、提示词变量、Skill、插件和已安装资源区域 |
| R39-02 | 输入不存在的 GitHub 仓库或 Skill 路径，点击“预览 Skill” | 页面显示失败原因；不出现安装成功、commit 或新增资源 |
| R39-03 | 输入不存在的项目插件目录，点击“预览并安装插件” | 页面显示失败原因；不出现安装成功或新增插件 |
| R39-04 | 关闭设置后再次打开 | 配置、资源列表和 revision 保留；失败提示不会伪装成成功状态 |
| R39-05 | 返回运行上下文和项目应用 | 设置操作不清空会话、应用实例、嵌入视图或运行轨迹 |

## 判定规则

- 只用 Electron 页面可见文字、按钮和状态判定。
- 失败路径必须有具体反馈，且不能出现“已安装”或“预览通过”。
- 本轮不修改代码；发现问题时完成整轮并沉淀报告，再进入下一轮修复。
