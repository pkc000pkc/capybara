# Capybara V2 页面回归计划（Round55）

## 目的

验证系统资源根迁移到用户级 `.capybara`、`@system` 资源依赖解析修复后，Electron 页面仍能正常使用项目、会话、聊天和资源治理入口。

## 前置条件

- 使用标准 `npm run desktop:start` 启动的最新构建。
- 已有可打开项目 `examples/qingjian-generated` 和空项目 `examples/ui-regression-clean-2026-11-14`。
- 页面通过 Electron IPC 连接本地 Runtime，不依赖旧 WebSocket 连接。

## 用例

| 编号 | 页面动作 | 通过标准 |
|---|---|---|
| R55-01 | 打开设置，查看全局模型、工具、Skill、Harness | 设置可打开；全局模型配置可见；系统工具/Skill/Harness 可列出，来源和错误状态可读 |
| R55-02 | 在当前会话发送一次只读指令 | 只产生一条用户消息；助手返回；执行过程显示 0 次工具调用或明确的完成步骤 |
| R55-03 | 关闭当前项目，再重新打开同一目录 | 项目从当前侧栏消失后可通过原生目录选择器恢复；会话历史和项目资源恢复 |
| R55-04 | 打开运行上下文并切换时间线、进程、子智能体、证据治理 | 四个视图可切换；当前项目的运行轨迹、进程和证据计数不串项目 |
| R55-05 | 打开项目应用面板并切换总览、内容与数据、资料来源 | 项目应用面板可打开；三个页签有内容或清晰空状态；项目切换后来源仍属于当前项目 |

## 记录要求

- 每个用例记录实际点击路径和可见结果。
- 失败时记录页面文案、所在页签和当前项目引用。
- 本轮只验证，不在点按过程中修改实现；如发现缺陷，结束本轮后单独修复并再开新轮。
