# Capybara V2 页面回归计划（Round63）

## 目的

验证 Round62 暴露的项目应用恢复时序修复：项目或会话切换期间，页面应显示明确的“正在恢复项目应用”状态，不得把异步加载中的临时空白状态展示为真实的“空白应用/未发布”。恢复完成后，项目应用版本、发布地址、研究结果和能力状态应一致。

## 用例

| 编号 | 页面动作 | 通过标准 |
|---|---|---|
| R63-01 | 重新启动 Electron，等待默认项目恢复 | 已发布研究应用直接恢复；若存在异步窗口，只显示恢复中，不显示空白应用/未发布。 |
| R63-02 | 从研究项目切换到另一个有效项目，再切回 | 另一项目显示自身状态；回切期间显示恢复中；完成后恢复 000682 研究结果、发布地址和版本。 |
| R63-03 | 点击当前研究项目行 | 当前项目不会被误显示为空白应用；若重新读取状态，显示恢复中后回到已发布应用。 |
| R63-04 | 切换历史会话并返回研究会话 | 消息和运行轨迹按会话恢复；项目应用面板在恢复过程中有明确状态，完成后保持项目级发布状态。 |
| R63-05 | 输入并发送 `hi` | 只产生一条用户消息，助手回复可见，输入框清空，发送按钮恢复禁用。 |
| R63-06 | 空输入按 Ctrl+Enter | 不新增消息，不触发运行，发送按钮保持禁用。 |

## 记录要求

- 使用最新 `apps/workbench/out` 构建并通过标准 `npm run desktop:start` 启动 Electron。
- 记录切换动作后的即时状态和恢复完成后的稳定状态，区分恢复中与真实空白应用。
- 本轮只做页面验证，不在页面操作过程中修改代码；完成后再根据报告决定是否继续修复。
