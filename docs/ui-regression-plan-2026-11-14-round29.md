# UI 黑盒回归计划（Round 29）

日期：2026-11-14  
范围：项目应用生命周期收据在运行上下文中的回放

## 目标

验证项目应用的启动、停止、重启和更新回滚收据能从持久化 trace 恢复到桌面运行上下文，并且页面能够按治理记录查看、筛选和复制这些收据。所有结论只以 Electron 页面操作后的可见状态为准。

## 用例

| 编号 | 页面操作 | 预期 |
| --- | --- | --- |
| R29-01 | 在健康项目应用上执行停止，再执行重启 | 应用回到 `running/healthy`，并产生可回放的 start/stop 生命周期收据 |
| R29-02 | 打开“查看运行上下文”并切换到“证据治理” | 页面出现“应用生命周期收据”分组，至少显示本轮 start/stop 收据 |
| R29-03 | 在治理筛选框输入 `stop` 或 `succeeded` | 结果数量和展开内容随筛选变化，收据 JSON 包含 operation、status、timestamp、instanceId 等字段 |
| R29-04 | 展开一条应用收据并点击“复制 JSON” | 页面显示“已复制”，复制内容是结构化收据 |
| R29-05 | 关闭并重新打开运行上下文，必要时重新打开项目 | 应用生命周期收据仍然存在，说明来源是持久化 trace 而非仅依赖当前内存事件 |

## 判定规则

- 应用生命周期收据和 ContextDocument 收据必须分组展示，不能混成一个计数。
- 收据必须保留 `receiptId`，并尽可能保留 `turnId / stepId / callId` 关联。
- 页面重新打开或项目重新连接后，历史收据不能消失。
- 过滤和复制只能读取页面已经回放的结构化记录，不能依赖聊天正文中的摘要。
