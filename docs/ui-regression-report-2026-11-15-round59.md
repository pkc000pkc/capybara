# Capybara V2 页面回归报告（Round59）

## 结论

本轮补测文件、视图、工具、帮助、设置和项目应用控制入口。文件菜单、设置、关于窗口、应用布局和嵌入看板均有可见反馈；视图菜单的“项目应用”和工具菜单的多个入口仍表现为统一运行上下文或保留提示，菜单动作矩阵尚未完全闭环。没有发现新的 P0/P1 运行阻塞。

## 新增缺口

1. 视图菜单中的“项目应用”入口没有表现出与工作区项目应用按钮一致的开关行为。
2. 工具菜单的多个入口仍共享运行上下文或保留提示，尚未形成定时、协作、进程、项目资源、能力演化、本地恢复和 Token 用量各自的可观察页面语义。
3. 文件菜单的项目文件和导出快照目前是明确的保留状态，尚未形成真实文件浏览或快照产物。
4. 菜单项在页面操作后的辅助功能树有时会短暂保留旧菜单或旧按钮索引，需要在后续修复轮确认是否只是观察缓存，还是存在可见状态与可访问名称不同步。

## 阶段判断

运行时、项目应用、设置资源和内嵌浏览器的主链路没有回归。当前产品仍可继续施工，但菜单功能不能按“入口已显示”视为完成；下一轮应优先统一菜单动作路由，给每个工具入口提供独立状态或明确空状态，并补齐项目文件与快照的真实产物闭环。
