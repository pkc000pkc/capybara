# Electron 页面回归计划（Round86）

日期：2026-11-15

本轮目标：验证产物治理按钮具备稳定的可访问名称和数据定位，并通过页面精确完成复核反馈。

## 用例

| ID | 场景 | 操作 | 预期 |
|---|---|---|---|
| K01 | 按钮唯一定位 | 打开 qingjian-generated 的“资料来源”页，读取无障碍树 | 每个产物操作按钮带有包含 artifactId 的唯一名称；按钮带有 action/id 数据属性 |
| K02 | 精确复核 | 使用无障碍树定位一个 `quarantined` 产物的“复核”按钮 | 页面状态栏显示 `artifact has no project file path` 等明确原因 |
| K03 | 精确接受 | 使用无障碍树定位另一个 `quarantined` 产物的“接受”按钮 | 页面状态栏显示审核成功，目标卡片变为 `accepted` |
| K04 | 页面刷新恢复 | 切换空项目再切回 qingjian-generated | K03 的 accepted 状态仍然存在，当前项目没有旧项目反馈泄漏 |

## 通过标准

- K01 必须能从页面无障碍树区分同名操作。
- K02、K03 必须不依赖坐标猜测即可完成。
- K04 必须证明治理状态仍由项目级索引恢复。
- 页面操作期间不修改代码；完成后写入 `docs/ui-regression-report-2026-11-15-round86.md`。
