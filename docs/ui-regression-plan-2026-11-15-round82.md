# Electron 页面回归计划（Round82）

日期：2026-11-15

本轮目标：补齐 Round79/80 阶段性审查中仍缺少页面证据的项目应用、嵌入浏览器、产物治理和历史运行轨迹。不在页面操作过程中修改代码。

## 用例

| ID | 场景 | 操作 | 预期 |
|---|---|---|---|
| A01 | 已发布项目应用打开 | 在 qingjian-generated 项目应用页点击“打开应用” | 进入系统托管的嵌入应用，显示行情看板页面；项目应用状态显示已打开或运行中；不出现原始 IPC 错误 |
| A02 | 嵌入浏览器生命周期 | 在应用视图中执行地址导航、刷新、后退、前进，再关闭视图 | 地址和页面内容按动作更新；关闭后回到项目应用页；不会把浏览器页面混入主聊天区 |
| A03 | 产物治理反馈 | 在资料来源/项目应用页对一个待复核产物执行“复核”，观察状态和提示 | 产物状态改变并显示即时反馈；刷新或重新进入后状态仍一致；来源和哈希信息不丢失 |
| A04 | 历史超时轨迹 | 打开 ui-regression-clean-2026-11-14 的超时会话，查看运行上下文的时间线和进程 | 可看到模型阶段、工具/脚本进程、超时终态、耗时和失败原因；进程状态不会伪装成成功 |
| A05 | 上下文页签一致性 | 在历史运行上下文中依次查看时间线、进程、子智能体、证据治理 | 各页签计数与内容来自同一会话快照，turnId/stepId/callId 关联不出现跨项目或跨会话串线 |

## 通过标准

- A01/A02 的浏览器动作必须在 Electron 页面中可观察，且结果能回到项目应用状态。
- A03 的治理操作必须有页面反馈和持久化后的再次读取证据。
- A04 的超时结果必须同时出现失败原因和进程收束状态。
- A05 不允许出现旧项目的轨迹、产物或治理计数。
- 本轮页面操作期间不改代码；完成后写入 `docs/ui-regression-report-2026-11-15-round82.md`，再决定是否需要修复轮次。
