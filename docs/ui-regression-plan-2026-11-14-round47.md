# UI 黑盒回归计划（Round 47）

日期：2026-11-14  
范围：系统资源统一规则与项目切换竞态修复后的 Electron 页面回归

本轮在 Round46 报告完成后执行，不在测试过程中修改实现。重点验证空项目不再复制系统文件工具、系统默认 Skill 在页面和运行时都可见，以及快速切换项目时旧资源响应不会覆盖当前项目。

## 测试前提

- 使用最新 Backend 构建和 Workbench 生产构建启动标准 Electron。
- 使用已登记的 `ui-regression-clean-2026-11-14`、`qingjian-generated` 两个项目。
- 页面操作只通过 Electron 窗口完成；磁盘与 API 只用于测试后核对，不代替页面证据。

## 用例

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| R47-01 | 打开空项目，进入“设置、提示词变量与资源” | 文件工具显示“来源：系统回退”；系统 `project-files` Skill 可见；项目目录不显示复制后的工具来源 |
| R47-02 | 切换到 `qingjian-generated`，重新打开设置 | `project-files` 仍为系统回退，`openai-docs` 显示为项目资源，项目应用和历史会话保持 |
| R47-03 | 在空项目与 `qingjian-generated` 之间快速连续切换并重开设置 | 资源列表、变量和目录修订始终属于当前项目，不出现旧项目 Skill 或工具 |
| R47-04 | 在空项目发送一条只读指令并打开运行上下文 | 聊天、系统默认工具、时间线和进程状态可正常工作，工具来源与设置页一致 |
| R47-05 | 关闭设置、关闭运行上下文，再切换项目后重开 | 面板状态可恢复，资源结果不串项目，应用空状态/研究应用状态保持各自项目 |
