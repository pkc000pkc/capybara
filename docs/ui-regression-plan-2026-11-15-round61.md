# Capybara V2 页面回归计划（Round61）

## 目的

补测 Round60 未覆盖的主导航、项目搜索与会话切换、运行上下文页签、项目应用页签/控制和基础输入发送链路。本轮只通过标准 Electron 页面操作，先完整记录结果，再决定是否集中修复；测试过程中不修改代码。

## 用例

| 编号 | 页面动作 | 通过标准 |
|---|---|---|
| R61-01 | 检查顶部后退/前进、项目名和本地工作服务状态 | 禁用态正确，项目名与服务状态和当前页面一致，无重复菜单。 |
| R61-02 | 最小化并恢复窗口；最大化并还原窗口 | 窗口可恢复，主区、侧栏和项目应用面板不重叠，项目状态不丢失。 |
| R61-03 | 在搜索框输入不存在的词、清空，再输入当前项目名 | 无匹配时有明确空状态；清空恢复列表；项目名搜索不误隐藏当前项目。 |
| R61-04 | 展开/收起当前项目，切换两个历史会话后返回原会话 | 会话列表层级和消息内容与会话对应，不产生重复或串线。 |
| R61-05 | 打开运行上下文，依次查看时间线、进程、子智能体、证据治理并关闭 | 四个页签可切换，计数和空状态可理解，关闭后主区保持不变。 |
| R61-06 | 项目应用总览→内容与数据→资料来源，再回到总览 | 页签可切换，内容/来源区域有数据或明确空状态，无页面报错。 |
| R61-07 | 点击应用运行状态、浏览器网关、市场研究状态和“查看运行差异” | 每个状态入口有可观察结果或明确不可用原因，不静默。 |
| R61-08 | 输入 `hi`，观察发送按钮并点击发送；检查用户消息、助手结果和输入框 | 只产生一条用户消息；发送状态、结果/错误和输入清空行为可见。 |
| R61-09 | 在空输入状态按 Ctrl+Enter | 不产生空消息，发送按钮保持禁用或给出明确提示。 |

## 记录要求

- 使用已启动的标准 Electron 窗口，仅通过页面点击、键盘和原生窗口控制操作。
- 每个用例记录开始状态、操作、页面可见反馈、结果和缺陷编号。
- 先完成全部用例再修改实现；若发现缺陷，另起修复轮并复测本轮失败/部分通过项。
- 本轮不安装外部资源、不修改模型配置、不删除项目或会话数据。
