# Capybara V2 页面回归报告（Round62）

## 结论

本轮在重新构建并通过标准 `npm run desktop:start` 启动的 Electron 页面上，验证了启动恢复、历史会话切换、跨项目切换、回切和单条消息发送。启动恢复、会话轨迹恢复和基础发送可用；项目切换后应用最终能够恢复，但切换期间会先短暂显示“空白应用/未发布”，说明项目应用状态恢复仍不是原子操作。

## 本轮新增缺口

1. **项目应用恢复不是原子状态（P1）**：项目或会话切换时，代码先清空 `applicationRuntime` 和 `marketResearch`，异步查询完成后再填回。页面因此会短暂展示“空白应用/未发布”，用户可能误以为发布内容丢失。
2. **切换动作缺少恢复中状态（P2）**：异步恢复期间没有“正在恢复项目应用”的明确状态，也没有冻结应用操作入口；应用面板的临时空状态与真实项目状态混在一起。

## 阶段判断

Round62 证明桌面重启、会话回放、跨项目隔离和发送闭环可以继续使用；项目应用数据最终能够恢复，但切换过程仍存在可见的状态闪烁。下一步应把项目应用恢复改为带项目/会话代数的统一快照加载，至少在恢复完成前保留旧快照或显示明确的恢复中状态，然后重新复测 R62-02 和 R62-04。
