范围：应用视图状态、应用失败反馈、设置中的 Skill/插件入口

## 目标

补齐 Round 32 留下的三个页面边界。测试期间不修改代码；先完成全部点按和记录，再集中判断是否需要局部修复。

## 用例

| 编号 | 页面操作 | 预期 |
| --- | --- | --- |
| R33-01 | 在项目应用面板点击“打开应用”，再分别点击“展开”和“收起” | 内嵌浏览器视图与项目应用面板的状态变化可见，主区不被遮挡；无视图和有视图两种状态语义清晰 |
| R33-02 | 停止当前项目应用后点击“打开应用”和相关能力入口 | 页面显示失败/不可用原因，不能继续显示旧地址、旧 PID 或健康状态，也不能把失败说成成功 |
| R33-03 | 在设置中保持 GitHub 仓库和 Skill 路径为空，点击“预览 Skill” | 显示明确输入校验或失败原因，不能静默无响应；“安装 Skill”保持禁用或给出原因 |
| R33-04 | 在设置中保持插件目录为空，点击“预览并安装插件” | 显示明确输入校验或失败原因，不生成半成品资源 |
| R33-05 | 关闭设置、应用视图和运行上下文后重新打开当前项目 | 失败状态、应用状态和会话上下文不串线；可继续查看历史轨迹 |

## 判定规则

- 只以页面实际可见反馈判定，不用代码或缓存替代页面验收。
- “明确失败/不可用原因”算页面行为通过，但记录为产品边界；静默无反馈算失败。
- 第一轮完成后才允许修改实现。
