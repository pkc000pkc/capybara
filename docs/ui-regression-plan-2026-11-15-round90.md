# Electron 页面回归计划（Round90）

日期：2026-11-15

本轮目标：定向验证工具失败后的 Runtime 收束、重试行为和关联信息。

## 用例

| ID | 场景 | 操作 | 预期 |
|---|---|---|---|
| O01 | 无效文件参数 | 发送“只调用一次 read_file 读取一个确定不存在的文件 `__capybara_missing__.txt`，失败后立即停止，不要重试、不要修改文件” | 页面显示一次明确工具失败，带工具名、参数摘要、错误原因和失败耗时；任务进入失败或可解释完成态。 |
| O02 | 失败过程可见 | 失败期间打开运行上下文 | 时间线能区分模型阶段、失败工具调用、结果回传和重试（若有）；失败调用与当前运行关联。 |
| O03 | 失败后恢复 | 失败任务结束后发送“只回复 OK，不调用工具” | Runtime 回到可用状态，后续请求正常完成；失败轨迹仍可回放。 |
| O04 | 页面按钮回归 | 在失败任务结束后打开“查看执行过程”和“查看运行上下文”，切换时间线/进程/证据治理 | 失败步骤、耗时、进程状态和治理记录能从按钮入口访问，不出现空白或跨会话内容。 |

## 通过标准

- O01 重点判断是否发生无界重试；若发生，记录实际次数和每次错误。
- O02 必须记录页面可见的阶段、工具名、错误和关联标识。
- O03 必须证明失败不会阻塞后续任务。
- O04 只做页面操作，不修改代码；本轮完成后先写报告，再决定是否修复。
