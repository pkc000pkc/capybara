## 发现的问题

### R80-APP-001：空白项目点击启动应用时显示原始 IPC 错误

复现步骤：

1. 切换到 `ui-regression-clean-2026-11-14`；
2. 打开“项目应用”；
3. 点击“启动应用”。

实际结果：

```text
Error invoking remote method 'capybara:application-start':
Error: application ui-regression-clean-2026-11-14 has no start command
```

项目应用仍显示“已停止”，但错误以原始 Electron Remote Method 文本出现在聊天工作区底部。对于没有 `start` 命令的空白项目，系统应在应用面板显示清晰的能力门禁和下一步，而不是把 IPC 异常直接暴露给用户。

建议修复方向：

- 应用面板在启动前显示“未配置启动命令”；
- 启动按钮显示为不可用或转为“配置运行入口”；
- 错误详情仍可进入运行上下文，但用户主界面只显示可理解的原因；
- 不改变 Runtime/Application Supervisor 的权限边界。

### R80-APP-002：项目切换期间运行上下文有短暂旧数据

切换项目后，项目应用明确显示“恢复中”，但运行上下文面板在等待新 Runtime Snapshot 到达前短暂保留了上一个项目的计数和治理内容。随后面板正确更新为新项目数据，最终没有发现跨项目持久串线。

建议在项目切换时同步把运行上下文置为 `hydrating` 或清空可见数据，直到新快照到达，避免用户在短暂窗口内误读旧项目状态。

## 未完成或仅部分完成的用例

- 浏览器后退/前进的最终 URL 在快速连续点击时不够容易判定，本轮确认了刷新、地址导航和关闭；后退/前进需要单步等待的专门回归。
- 资料来源页的“复核/接受/拒绝”按钮本轮确认可见，尚未改变现有产物状态，避免污染历史测试数据；后端审核 API 已有自动化覆盖。
- 空白项目没有合法启动命令，因此无法在该项目上继续验证应用运行、停止和重启的成功路径；已发布的 `qingjian-generated` 应用打开路径通过。
- 本轮没有执行真实外部网络下载、股票研报重下载和真实模型长链路，以避免重复产生外部副作用；这些仍属于端到端验收项。
