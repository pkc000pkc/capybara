## 新发现的策略边界

空项目中的 `project-files` 当前路径为 `tools/files/manifest.json`，页面标记为“来源：项目资源”；`qingjian-generated` 中同一工具则标记为“来源：系统回退”。这说明空项目初始化阶段可能把系统工具复制进了项目，实际表现不是纯粹的“项目优先、找不到则系统回退”。需要在资源策略中明确：系统托管工具是否允许初始化时复制，还是应始终保持系统来源并在项目中按回退规则解析。

新构建启动时，空项目的应用状态轮询还在 Electron 日志中报告 `application ... has no start command`。页面能回到空白应用状态，但宿主层应把“没有应用”作为正常空状态处理，避免产生错误日志。

## 结论

来源表达和错误定位已经达到可审查水平，项目隔离和 Skill 安装链路保持稳定；资源加载策略的“复制 vs 系统回退”语义仍需收敛，插件有效安装、依赖冲突/复用和同名覆盖仍未完成验收。
