# UI 黑盒回归计划（Round 31）

日期：2026-11-14  
范围：000682 市场研究与项目应用业务闭环

## 目标

验证用户能够从项目应用入口发起 000682 研究，并在页面上看到浏览器研究、研报与交易数据、Python 分析、看板发布和建议结果的连续状态；结果必须带有步骤、证据和不确定性表达。

## 用例

| 编号 | 页面操作 | 预期 |
| --- | --- | --- |
| R31-01 | 打开项目应用并检查宿主能力状态 | 应用运行时、浏览器网关和市场研究显示可用或给出具体不可用原因 |
| R31-02 | 点击“市场研究”能力入口，等待结果完成 | 页面进入 000682 研究状态，显示进行中/完成/失败及具体阶段 |
| R31-03 | 查看研究结果卡片 | 至少能区分交易数据、最近三年研报、Python 特征分析、看板发布/打开和建议步骤 |
| R31-04 | 查看证据、产物和建议 | 结果显示来源/证据和产物引用；建议标注待人工审查、风险和不确定性 |
| R31-05 | 打开行情看板 | Electron 内嵌浏览器或项目应用页面打开看板，能看到真实页面而非占位错误 |
| R31-06 | 打开运行上下文 | 时间线、进程、证据治理与市场研究结果属于同一项目和当前会话，失败时可定位阶段 |
| R31-07 | 关闭并重新打开项目应用/运行上下文 | 已完成研究的状态、证据和应用版本仍可恢复，不能只保留聊天摘要 |

## 判定规则

- 研究不能只返回“已完成”而没有阶段、证据或产物。
- 研报、交易数据、Python 分析、看板和建议必须分别有状态；一个阶段失败不能伪装成整条链路成功。
- 交易建议只作为待审查结果展示，不得自动执行买卖动作。
- 页面黑盒结果以实际点击后的可见状态为准，不能用代码或缓存推断未显示的结果。
