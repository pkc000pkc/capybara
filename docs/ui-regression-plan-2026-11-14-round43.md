# UI 黑盒回归计划（Round 43）

日期：2026-11-14  
范围：项目级/系统级工具、Skill、插件资源治理与项目隔离

## 目标

确认设置页面展示的资源目录与运行时实际加载边界一致：资源有明确来源和 revision；无效安装给出结构化错误；项目切换不会把一个项目的资源带入另一个项目。

## 用例

| 编号 | 页面操作 | 预期 |
| --- | --- | --- |
| R43-01 | 在 `qingjian-generated` 打开项目设置并查看资源目录 | 能看到项目级和系统级资源来源、类型和 revision；同一资源不重复显示 |
| R43-02 | 对已存在的有效 Skill 或插件执行预览/安装 | 页面显示来源、版本/提交和安装结果；目录 revision 改变；会话和 000682 研究状态保持 |
| R43-03 | 提交不存在的 Skill/插件来源 | 页面显示资源级错误（仓库或目录不存在），不显示安装成功；关闭重开设置后不把历史错误伪装成当前成功状态 |
| R43-04 | 切换到空项目并查看资源目录 | 空项目只显示系统回退资源和自身资源；不出现 `qingjian-generated` 的项目级资源 |
| R43-05 | 从空项目切回 `qingjian-generated` | 000682 应用、会话、研究产物和原项目资源恢复；空项目资源不串入原项目 |

## 判定规则

- 先完成全部页面用例，再决定是否修复实现。
- 不能以 API 返回或目录文件存在代替页面证据。
- 安装成功必须同时有页面反馈和资源目录/revision 变化。
- 资源隔离以切换前后两个项目的页面内容和设置目录共同判定。
