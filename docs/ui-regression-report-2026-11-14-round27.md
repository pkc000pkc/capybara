### R27-02：更新成功

- 页面保持 `running/healthy`，实例端口重新分配，聊天区显示“应用已更新到新版本”。

### R27-03：更新失败并回滚

- 在项目源目录加入 `fail-health` 测试标记，使新版本的所有健康探针返回 HTTP 503。
- 通过页面再次点击“更新”。
- 页面显示：

```text
应用更新失败，已回滚到 version-1794689614346-2a133bb0：HTTP 503 at /
```

- 应用状态回到旧版本实例，错误原因可见，没有误报为“应用已更新到新版本”。

测试过程中还发现，健康检查会依次尝试 `/api/health`、`/health` 和 `/`；只有让所有探针都失败，才能构成可靠的失败夹具。该前置条件已修正并重新验证。

### R27-04：运行上下文回放

- 运行上下文可以打开，但当前失败更新项目的上下文显示 `时间线 0 / 进程 0 / 证据治理 0`。
- 页面没有把 application update 的失败和 rolled_back 收据作为运行上下文记录展示，因此本用例判定为未完成，保留为下一轮缺口。

### R27-05：停止和重启

- 点击“停止”后，页面收束为“已停止 / 本地地址待分配”，旧 PID、端口和健康状态不再作为运行状态展示。
- 在已经故意损坏的版本上点击“重启”，页面显示 `HTTP 503 at /`，失败阶段可定位；健康版本重启成功路径需要下一轮单独补测。
