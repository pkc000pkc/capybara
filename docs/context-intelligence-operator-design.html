Context Intelligence Model · 算子级设计

单模型多任务上下文编译器。每个算子只做一类可验证的转换；模型提出结构化结果，Runtime 负责版本、证据、权限和状态提交。

蓝：编码与语义理解青：缓存与记忆金：结构化解码与计划绿：确定性校验红：冲突与人工复核

总数据流

InputNormalize消息、工具结果、Markdown、缓存
SemanticEncode语义单元、实体、证据表示
TaskRoute单模型多任务调用
ConstrainedDecodeTyped Proposal / Diff
RuntimeApply校验、提交、receipt

编码与理解算子

1. InputNormalize

raw → NormalizedBlock[]

把不同来源转换为统一输入块，保留来源和原始内容的可追溯关系。

输入
ChatMessage、ToolResult、Markdown、MemoryRecord
处理
识别来源、时间、媒体类型、原始 hash；切分 section / entry / evidence 边界
输出
带 blockId/sourceId/type/capturedAt/contentHash 的标准块
副作用
无；只产生候选输入
失败
来源缺失、编码错误、内容无法解析 → 标记 malformed

2. SemanticEncode

NormalizedBlock[] → SemanticUnit[]

从非结构化块中抽取事实、事件、状态、约束、未知和后续事项。

输入
标准块 + 当前任务 + 相关活动条目
处理
共享 Transformer 编码 token；entry/evidence 边界通过特殊标记编码
输出
entity/event/fact/state/constraint/open_question/plan
副作用
无；语义单元进入候选区
失败
低置信度或字段不足 → needs_more_evidence

3. EntityAlign

SemanticUnit + EntryIndex → EntityLink[]

判断新信息对应已有实体、事件或状态，避免相似文本被错误合并。

输入
新语义单元 + 实体索引 + 时间和来源信息
处理
结合名称、类型、ID、时间、关系和向量相似度进行对齐
输出
same / possible_same / different / unresolved
副作用
更新实体候选索引，不改变事实状态
失败
possible_same 或 unresolved → 禁止自动合并

4. RelationClassify

OldUnit + NewUnit → RelationDecision

判断新旧信息是重复、补充、覆盖、冲突、过期还是无关。

输入
已对齐的新旧语义单元及其 evidence
处理
比较实体、属性、时间、来源可信度和状态语义
输出
duplicate / refinement / supersedes / contradiction / new / expired
副作用
无
失败
证据不足时保留为 conflict 或 candidate

文档与记忆算子

5. DocumentPlan

SemanticUnit[] + RelationDecision[] → DocumentPlan

规划文档如何重组，避免每轮重新生成整篇 Markdown。

输入
当前信息条目 + 新语义单元 + 关系判断
处理
稳定章节排序；只操作受影响条目；保留 evidence 引用
输出
keep / merge / replace / conflict / new / archive 计划
副作用
无；计划等待 diff 生成
失败
出现跨实体合并或证据断链 → request_review

6. ArchiveScore

Entry + Task + MemoryValue → ArchiveProposal

判断当前条目是否可以从活动投影归档，同时保留长期记忆。

输入
条目、当前任务、重复度、时效、召回价值
处理
计算低相关性、被覆盖程度、token 成本、关键约束风险
输出
归档目标、理由、风险、recallKeys、protectedItems
副作用
无；不得直接移动条目
失败
关键约束或唯一证据风险高 → 保留 active

7. MemoryRecall

Task + Query → MemoryCandidate[]

从长期归档中召回与当前任务相关的信息。

输入
任务目标、实体、时间、未完成事项、检索结果
处理
实体、关键词、时间、向量和任务相关性多路排序
输出
带原始来源、证据、版本和召回理由的 candidate
副作用
只进入候选区，不直接恢复为事实
失败
时效冲突或证据过期 → stale / conflict

8. ProjectionSelect

Document + Candidates + Budget → ProjectionPlan

在 token 预算内选择当前大模型真正需要看到的内容。

输入
active entries、pending candidates、任务约束、字符预算
处理
保护目标/约束/未完成事项；按相关性和风险排序；生成反事实投影
输出
source IDs、selectionReasons、truncatedSections、contentHash
副作用
生成投影，不改变源文档
失败
预算不足以容纳保护项 → request_review

解码与提交算子

9. PlanToDiff

DocumentPlan → DiffProposal

将自然语言计划转换为有限操作集合，禁止模型直接重写 Markdown。

输入
DocumentPlan、目标条目、证据和文档 revision
处理
生成 add/replace/append/archive/recall/mark_conflict 操作
输出
Typed Diff：targetId、expectedHash、evidenceRefs、idempotencyKey
副作用
无；只提交 proposal
失败
目标不存在或 evidence 缺失 → rejected proposal

10. ConstrainedDecode

ModelLogits → SchemaValidOutput

在 token 级别限制输出，使模型只能生成合法的结构化协议。

输入
任务 schema、合法 ID 集合、模型 logits
处理
JSON Schema / grammar / token mask；枚举值和 ID 复制约束
输出
可解析的 Extract、Archive、Recall 或 Diff envelope
副作用
无
失败
schema 无法完成 → 有限修复；仍失败 → no-op / request_review

11. EvidenceGate

Proposal + EvidenceStore → GateDecision

检查每个事实变化是否由真实、存在且相关的证据支撑。

输入
proposal、evidenceRefs、source hash、观察时间
处理
检查引用存在、来源匹配、时效和候选状态
输出
accept / reject / needs_more_evidence
副作用
生成审计 receipt
失败
伪造、缺失或不匹配 → reject

12. RevisionApply

ValidatedDiff + Document → NewDocument

以确定性方式提交变更，处理并发、重复和冲突。

输入
通过门禁的 diff、当前 document revision
处理
校验 baseRevision、expectedHash、权限和 idempotencyKey
输出
新版本 ContextDocument + ApplyReceipt
副作用
更新 active/archive/candidate 状态
失败
stale revision → conflict；重复 key → 返回原 receipt

模型内部缓存与输出契约

缓存分层

L0 任务前缀：目标、约束、最近消息
L1 活动条目：当前投影候选
L2 语义摘要：章节、实体、事件状态
L3 归档记忆：原文、摘要、证据、embedding

KV Cache：只缓存当前请求的稳定前缀
Semantic Cache：长期保存，可版本化、可召回

稳定输出契约

模型输出 → grammar constrained decoding
           → JSON parse
           → Typed Envelope 校验
           → evidence / revision / hash gate
           → ApplyReceipt

字段必须包括：
operation, documentId, baseRevision,
targetId, expectedHash, evidenceRefs,
reasonCode, confidence, risk, idempotencyKey

安全状态流

raw input
  → candidate
  → evidence reviewed
  → proposal
  → accepted / conflict / rejected
  → active 或 archived

archived
  → recalled_candidate
  → evidence reviewed
  → accepted
  → active

任何一步都不能跳过 Runtime 校验。

原则：模型负责提出语义操作，Runtime 负责决定操作是否可以改变系统状态。

状态变化与流转

raw原始消息、工具结果、网页内容
candidate已抽取但尚未确认的语义单元
active已确认，可进入当前投影
archived长期记忆，可按需召回
conflict新旧证据矛盾，保留双方
stale来源过期或被新状态覆盖
recalled_candidate从归档召回，等待重新审核
rejected证据不足或协议校验失败
raw
  └─ InputNormalize → candidate
       ├─ EvidenceGate 通过 → active
       ├─ EvidenceGate 拒绝 → rejected
       ├─ 新旧信息不一致 → conflict
       ├─ 新版本覆盖旧版本 → 旧条目 stale
       └─ ArchiveScore 通过 → archived
                              └─ MemoryRecall → recalled_candidate
                                   ├─ 重新验证通过 → active
                                   ├─ 发现冲突 → conflict
                                   └─ 证据过期 → stale

active → ProjectionSelect → 当前模型投影
archived 不直接进入投影，必须经过 recalled_candidate。

状态变化原则：归档是可逆的投影变化；召回是重新进入候选审核，不会绕过证据门禁。

正向传播（Forward）

输入样本 x
  → Tokenizer(x)
  → Embedding + Position / Section 标记
  → Transformer Backbone
  → 共享隐藏状态 H
  → 任务路由 token 选择任务表示 H_task
  → Task-specific schema projection
  → logits
  → grammar mask / valid-ID mask
  → 结构化预测 ŷ
  → 与标注 y 比较生成 Loss

Loss = λ₁·L_token
     + λ₂·L_schema
     + λ₃·L_relation
     + λ₄·L_evidence
     + λ₅·L_diff
     + λ₆·L_archive

反向传播（Backward）

Loss
  → ∂Loss/∂logits
  → 通过 schema projection 反传
  → 通过 task route 反传到共享隐藏状态 H
  → 通过 Transformer layers 反传
  → 只更新 LoRA / adapter 参数
  → gradient clipping
  → optimizer step
  → 更新模型参数 θ

冻结项：base model weights、Runtime 规则、evidence store、文档状态。

多任务训练批次结构

共享部分

同一 Backbone θ_shared
同一 tokenizer
同一 entry / evidence 标记
同一基础上下文格式

任务标记：
<task=extract>
<task=align>
<task=relation>
<task=documentize>
<task=archive>
<task=recall>

任务损失与采样

一个 batch 可混合多种任务，
但每条样本只有一个主任务。

建议初始采样：
extract      25%
align        15%
relation     15%
documentize  15%
archive      10%
recall       10%
diff         10%

训练过程中按验证集表现调整 λ。

训练数据到系统状态的闭环

人工确认 / Runtime receipt / 任务结果
        ↓
构造训练样本：旧文档 + 新观察 + evidence + 目标操作
        ↓
模型正向传播：生成候选抽取、关系和 diff
        ↓
Loss 与人工目标 / 规则目标比较
        ↓
反向传播：更新 LoRA adapter
        ↓
离线评估：结构化成功率、事实准确率、归档风险、任务保持率
        ↓
通过门槛后才进入 Runtime shadow mode
        ↓
线上 receipt 继续产生新训练样本
