# UI 黑盒回归报告（Round 33）

日期：2026-11-14  
范围：项目应用停止态、应用视图关闭/重开、设置入口可达性和状态恢复

## 结论

R33-01、R33-05 通过；R33-02 通过状态收束但存在产品语义边界；R33-03、R33-04 本轮未形成有效页面证据，不能判定通过。测试期间未修改代码。

当前最需要澄清的是两个状态轴：

- 项目应用运行实例的状态（本轮页面显示“已停止”）；
- 已发布应用内容或本地看板宿主的可访问状态（停止后仍可通过本地地址打开看板）。

如果产品允许已发布静态内容在实例停止后继续查看，页面需要明确标注“已发布内容/静态宿主”；如果“停止应用”应当让用户无法打开应用，则当前“打开应用”行为应视为缺陷。

## 黑盒证据

### R33-01：应用视图和项目应用面板

- 通过项目应用入口打开 `000682` 行情看板，页面仍能展示研究闭环、21 条日线、3 个研报和待人工审查建议。
- 关闭项目应用面板后，主工作区恢复可操作；再次打开项目应用面板，研究闭环、证据来源和应用版本仍然存在。
- 本轮没有得到“展开/收起”在有内嵌视图状态下产生明确布局变化的证据；Round32 已记录无视图状态下该按钮没有可见变化。

判定：主路径通过；展开/收起语义仍待专门收敛。

### R33-02：停止应用后的打开行为

- 在应用面板点击停止后，页面显示 `已停止`。
- 停止态没有继续显示运行实例的 PID、端口或 `healthy` 文案；应用实例状态本身已收束。
- 停止态仍显示地址 `http://127.0.0.1:60727/applications/market-dashboard/v1/index.html`，并保留“打开应用”和“重启”按钮。
- 点击“打开应用”后，Electron 内嵌区域重新显示已发布的 `000682` 看板；页面没有给出“静态发布内容仍可访问”或“实例已停止但看板可读”的解释。
- 同一页面的“本地应用运行”区域仍显示 `运行中 / 运行版 v1 · 已生成本地地址`，与面板顶部的“已停止”同时出现，容易被理解为状态矛盾。

判定：运行实例停止状态通过；停止态与已发布看板宿主的状态表达为产品边界，暂不判定为实现失败，但不能作为“停止后应用完全不可访问”的验收证据。

### R33-03：空 Skill 路径校验

- 本轮从当前页面打开工具菜单后，设置菜单项可见，但没有形成进入设置页面的有效可见结果。
- 因此没有执行“保持 GitHub 仓库和 Skill 路径为空后点击预览 Skill”的页面操作。

判定：未复测。需要下一轮先确认设置入口的可达性，再验证空输入校验和安装按钮状态。

### R33-04：空插件目录校验

- 同 R33-03，本轮未进入设置中的插件管理区域。

判定：未复测。不能据此推断插件预览/安装逻辑通过或失败。

### R33-05：关闭并重新打开项目应用

- 关闭项目应用面板后，聊天区和主工作区保持可操作。
- 再次打开项目应用面板，`v1 · 已发布`、研究闭环、5 个研究步骤、来源证据和产物列表均恢复。
- 当前项目仍为 `qingjian-generated`，没有把其他项目的会话或应用状态带入。

判定：通过。

## 本轮新增缺口

1. **应用实例状态与发布内容状态未分离表达**：停止后仍保留本地地址并可打开已发布看板，且页面同时出现“已停止”和“本地应用运行中”。
2. **应用面板展开/收起没有稳定的状态反馈**：无视图状态下无可见变化，有视图状态本轮也没有形成可重复证据。
3. **设置入口需要专项可达性回归**：工具菜单能显示设置项，但本轮无法通过页面操作进入设置内容，Skill/插件空输入校验因此未完成。
4. **失败态按钮语义需要补充**：停止态的“打开应用”是打开静态发布内容、自动重启实例，还是只允许“重启”后打开，页面没有区分。

## 下一轮建议

- 用一个明确的“已发布内容宿主”和“运行实例”双状态样例复测停止、打开、重启三个动作，并为每个动作写出可见预期。
- 在可进入设置页后，分别验证空 Skill 路径、空插件目录、非法路径和有效路径四种输入，记录校验文案、按钮禁用状态和资源变化。
- 对“展开/收起”分别在无内嵌视图、有内嵌视图、面板关闭后三种状态点按，要求每次都有布局或按钮文案变化。
