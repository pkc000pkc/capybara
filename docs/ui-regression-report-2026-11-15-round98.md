# UI 页面全量回归报告（Round 98）

## 结论

本轮按页面操作完成了菜单、侧栏、项目、会话、运行上下文、项目应用、内嵌浏览器、设置与资源管理入口的回归。主要可见能力已经形成可操作闭环，页面能够展示运行轨迹、进程、子智能体和应用生命周期收据。

本轮发现一个可稳定复现的页面状态缺陷：从“打开本地项目”进入目录选择器后取消，当前项目选择被清空，工作区变为空白状态；项目列表仍然存在，重新选择项目才能恢复。该问题不涉及运行协议，可在 UI 状态处理层修复。

## 证据与运行轨迹观察

运行上下文已经能把用户会话、模型阶段、工具调用、进程、子智能体和应用生命周期放在同一页面体系中。工具失败也能显示 `RUNNER_FAILED`、`ENOENT`、耗时和结果 artifactId，满足页面侧的可定位性要求。

现有子智能体失败场景仍暴露一个运行时协议缺口：父层 `delegate_task` 收据显示 `status=succeeded`、`ok=true`，子代理内部的 `read_file` 才显示 `status=failed`。页面可以追到内部失败，但父任务状态没有把子任务失败向上汇总，容易造成完成判断偏差。该问题属于 Runtime/A2A 状态聚合，需要单独列入下一阶段验收。

## 修复前的缺口清单

1. **打开项目取消会清空当前选择（P1）**：取消系统目录选择器应保持原项目和原会话，不应进入无项目空工作区。
2. **A2A 父状态未汇总子失败（P1）**：父 `delegate_task` 成功不能掩盖子代理内部工具失败，父收据、完成判断和页面状态应保留失败传播关系。
3. **部分菜单占位入口缺少明确反馈（P2）**：文件菜单中的项目文件、导出项目快照，以及部分工具占位入口需要显示可验证的状态反馈或明确的未配置原因，避免点击后无可观察变化。

本轮没有修改代码；当前工作区已恢复为 `qingjian-generated` 项目，项目列表恢复为 3 个已登记项目。
