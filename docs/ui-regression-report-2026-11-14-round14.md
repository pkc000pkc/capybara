## 新发现的高优先级问题

### R14-P0-01：历史会话恢复超过模型输入上限

页面错误：

`model input requires 14033 tokens but the configured limit is 14000; only builtin.cache is compressible`

触发方式：

1. 打开项目；
2. 点击历史会话“请调研股票投资方法……”；
3. 等待会话恢复。

影响：

- 历史会话无法稳定回放；
- 用户无法继续该会话；
- 运行上下文和消息恢复闭环被打断。

这不是单纯的 UI 文案问题，而是会话恢复时上下文预算没有在发送模型请求前完成有效裁剪。需要将它作为下一轮修复的最高优先级。

### R14-P1-02：新会话列表出现重复

页面同时出现两条“新会话 · 尚未运行”。本轮测试中多次点击新会话后观察到重复条目，且没有清晰的创建中/已提交状态。

影响：

- 用户无法判断两个条目是否是两个独立会话；
- 可能造成 session ID、运行上下文和消息串线；
- 直接违反“点击一次只新增一条、连续点击产生独立会话”的验收要求。

### R14-P1-03：视图菜单入口是占位行为

以下入口没有完成对应交互：

- 项目侧栏：不隐藏侧栏；
- 深色外观：不切换主题；
- 关于概念稿：只显示“入口已保留”。

### R14-P1-04：设置资源展示重复

上一轮设置面板已观察到两条 `capybara-system · harness`。本轮重开项目后仍保留历史资源展示问题，项目优先/系统回退来源没有在界面中表达。

## 已通过的关键产品链路

本轮可确认以下链路已具备产品化基础：

```
打开项目
  → 选择会话
  → 读取消息和 Trace
  → 查看时间线
  → 展开工具调用参数/结果
  → 查看进程/子智能体状态
  → 打开项目应用
  → 内嵌浏览器展示页面
  → 停止/重启应用
  → 关闭项目
  → 重新打开项目
```

## 本轮未完成的高风险场景

以下场景已经列入用例，但本轮没有制造真实运行条件，因此暂不判定通过：

- 工具超时；
- 脚本进程非零退出；
- 真实子智能体委派；
- 断线重连后的完整 Trace 回放；
- 应用更新失败后的回滚；
- 多项目并行切换时的进程隔离；
- Ctrl+Enter 与快速重复发送的组合压力场景。

## 修复顺序

1. 先修复历史会话恢复的上下文预算超限；
2. 修复新会话重复创建/重复渲染；
3. 修复资源目录去重和来源标识；
4. 实现项目侧栏折叠与深色外观；
5. 再做第二轮完整页面回归；
6. 第二轮之后补齐异常、重连、子代理和回滚场景。
