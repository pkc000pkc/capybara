# UI 页面回归测试计划（Round 96）

## 目标

验证 RuntimeLoop 的重复失败保护已经通过真实 Electron 页面生效，并确认失败后的会话仍可恢复、已发布项目应用仍可打开。

## 测试环境

- Electron 桌面应用（当前构建）
- 项目：`qingjian-generated`
- 测试方式：仅通过页面可见控件、页面输入和页面显示结果
- 证据要求：记录会话、工具调用、子任务、收据、错误码和页面最终状态

## 测试用例

### R96-01：子任务重复失败自动终止

通过聊天输入：

> 请委派一个子智能体，只读读取项目根目录下确定不存在的 `__capybara_child_missing_round96__.txt`。子任务失败后立即停止，不要重试，不要修改任何文件。父任务需要保留 childId、子任务工具调用、失败收据和证据，并在最终回复中说明。

预期：

1. 页面显示父任务和子任务的工具调用链。
2. 缺失文件读取失败，显示具体错误原因、失败收据和证据引用。
3. 相同委派动作最多自动重复一次；第二次相同失败后，父任务进入确定性失败状态，错误码为 `REPEATED_TOOL_FAILURE` 或等价的明确重复失败错误。
4. 不需要手动点击“停止本轮”才能结束。
5. 页面保留 childId、工具调用、失败结果及父任务最终状态。

### R96-02：失败后的会话恢复

在 R96-01 结束后输入：

> 只回复 OK，不调用工具。

预期：

- 新请求正常完成并显示 `OK`。
- 本轮不产生工具调用。
- 上一轮失败轨迹仍可见。

### R96-03：失败后打开已发布项目应用

通过右侧项目应用面板打开当前已发布应用。

预期：

- 应用视图可以打开。
- 应用内容和运行状态可见，不因上一轮 Agent 失败而丢失。
- 关闭后可以再次打开。

## 通过标准

- R96-01 不需要人工停止，且失败原因和重复失败策略可见。
- R96-02、R96-03 在同一页面会话中通过。
- 若任一预期不满足，先记录页面证据，再修复代码并重新构建、重启和回归。
