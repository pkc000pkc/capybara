# Capybara Workbench UI 回归报告（2026-11-14 第三轮）

本轮按 [UI 回归测试用例](./ui-regression-test-cases-2026-11-14.md) 执行，先完成上一轮报告，再修复一个明确的桌面边界问题，重新构建并用标准命令启动 Electron，最后只通过页面、原生窗口和应用内嵌页面操作验证。

## 本轮修复

第二轮发现关闭项目时桌面 IPC 调用不存在的 `runtimeManager.closeWorkspace`，页面出现 remote method 错误且项目没有移除。

已在 `apps/workbench/electron/backend-runtime-host.cjs` 补齐 `closeWorkspace`：按工作区或项目路径找到全部运行时，保存会话状态、取消持久化定时器、解除事件订阅、关闭 RuntimeLoop 并清理运行时注册表。随后执行：

```text
npm run desktop:build --workspace=apps/workbench
npm run desktop:start --workspace=apps/workbench
```

构建成功，Electron 标准启动成功。启动时仍有 Windows Chromium cache 拒绝访问的日志，但不影响页面加载和交互。

## 当前可用范围

本轮后确认可用的闭环是：

```text
本地项目登记
  → 项目/会话选择
  → 会话发送
  → 模型阶段摘要与执行时间线
  → evidence 详情
  → 项目应用启停
  → Electron 内嵌浏览器打开/关闭
  → 项目关闭与运行时清理
```

## 仍需处理的缺口

### R1-02：旧 `coding` 会话的模型错误后状态未恢复

第一轮在 `coding` 项目已有会话中发送编程请求时，页面显示 401 错误，随后仍停留在“工作中/等待模型输出”；点击“停止本轮”没有清掉该运行状态。第二轮和第三轮没有继续复测该项目，因为第三轮已用关闭项目用例验证并移除了 `coding`。

这属于 RuntimeLoop/错误态恢复问题，不能仅按 UI 文案修复。下一轮应在重新打开 `coding` 项目后复测：

1. 模型返回 401 或网络失败；
2. 页面是否产生明确失败事件；
3. 运行状态是否自动回到可发送；
4. 停止本轮是否能结束挂起运行；
5. 重开会话后是否可回放失败轨迹。

### 业务场景仍未完成全量验收

股票调研、研报下载、日线数据获取、Python 特征分析、看板生成/打开、交易建议等 H01-H06 需要在真实浏览器和工具调用链上逐项执行。当前第三轮只验证了无工具的会话、应用生命周期和执行轨迹，因此这些业务场景仍不能标记为通过。

### 本轮没有改变的运行日志

Electron 启动日志仍会出现 Chromium disk cache 的 Windows 权限错误。当前不阻断工作台、模型请求或内嵌应用，但应作为发布前环境问题单独处理，避免把它与业务失败混淆。

## 结论

项目关闭边界已达到可用状态，核心 UI、会话、应用容器和执行轨迹闭环在第三轮通过。当前不能称为“全部功能验收通过”，阻塞项是旧编程会话的 401 错误态恢复，以及 H01-H06 业务链路尚未完成真实页面回归。
