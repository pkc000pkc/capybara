# Capybara Workbench 黑盒回归测试用例

日期：2026-11-14  
范围：桌面应用可见页面、菜单、按钮、输入、运行上下文、项目应用和项目生命周期。  
方法：只通过桌面应用页面观察、点击、输入和键盘操作验证；不以代码级测试代替页面验收。

## 测试约定

- 每个用例先记录页面初始状态，再执行步骤；步骤中每次点击后重新观察页面。
- “通过”表示页面动作有可见反馈，且反馈与预期一致；“失败”记录实际结果、页面位置和可复现步骤。
- 涉及真实外部网络、文件下载、模型请求或应用启动的动作，只验证应用内的状态、进度、结果和错误展示，不把外部服务返回内容当作页面功能本身的唯一证据。
- 首轮测试不修改实现；所有缺陷先沉淀到首轮报告，首轮完成后再集中修复允许修复的前端或局部逻辑问题。

| A06 | 点击原生菜单“工具” | 菜单打开，菜单项可见且无重复项 |
| A07 | 点击原生菜单“帮助” | 菜单打开，菜单项可见且无重复项 |

## B. 侧栏、项目和会话

| ID | 操作 | 预期 |
|---|---|---|
| B01 | 点击“新会话” | 只创建一个新会话；主区切换到该会话且会话列表出现一条对应记录 |
| B02 | 连续点击两次“新会话” | 两次动作各创建一条独立会话，不出现重复渲染或错误选中 |
| B03 | 点击“打开本地项目”，选择有效目录 | 项目打开，侧栏显示项目，默认创建或加载项目级 `.capybara` 状态 |
| B04 | 选择空目录打开项目 | 页面显示空项目状态，可从该状态开始工作，不显示不存在的项目 |
| B05 | 点击项目行展开/收起 | 项目下的会话列表只显示属于该项目的会话，展开状态可切换 |
| B06 | 点击项目下已有会话 | 主区加载正确会话记录，标题、消息和运行状态与该会话一致 |
| B07 | 在项目/会话搜索框输入关键词 | 列表按关键词过滤；清空关键词恢复完整列表 |
| B08 | 点击项目行关闭项目入口 | 项目从当前工作区关闭；未关闭的其他已存在项目仍可见 |
| B09 | 关闭后重新打开同一项目 | 项目恢复，历史会话和项目应用状态可见 |
| B10 | 观察无效/已删除项目列表 | 不存在的目录不显示；上次打开且仍存在的项目可以显示 |

## C. 主区导航与工作控制

| ID | 操作 | 预期 |
|---|---|---|
| C01 | 点击侧栏折叠/展开按钮 | 侧栏宽度和主区布局切换一次，按钮状态与布局一致 |
| C02 | 点击“查看运行上下文” | 打开运行上下文面板或视图，当前会话上下文可见 |
| C03 | 点击“项目应用” | 打开项目应用面板；关闭按钮能关闭面板 |
| C04 | 点击“立即运行/执行过程” | 当前会话进入运行态，页面显示运行中状态和可观察进度 |
| C05 | 运行中点击“停止本轮/暂停任务” | 运行停止或暂停，状态和按钮文案随之更新 |
| C06 | 空闲时观察运行控制按钮 | 不应显示错误的“运行中”状态，禁用/可用状态合理 |
| C07 | 从运行态返回会话列表再回到会话 | 运行状态和已产生的轨迹不丢失 |

## D. 聊天输入与消息

| ID | 操作 | 预期 |
|---|---|---|
| D01 | 在输入框输入普通文本 | 文本显示在唯一的输入框中，不出现第二个重复输入框 |
| D02 | 点击发送按钮 | 用户消息只出现一次；按钮有提交反馈，随后出现助手状态或明确错误 |
| D03 | 输入文本后按 Ctrl+Enter | 与点击发送等效，只发送一次，不重复提交 |
| D04 | 发送空文本 | 不发送空消息，页面给出合理的禁用或提示 |
| D05 | 请求读取文件 | 能看到模型阶段摘要、工具调用、工具结果、验证阶段和最终回复 |
| D06 | 请求执行代码 | 能看到脚本/进程运行状态、输出、验证结果和最终回复 |
| D07 | 工具失败或超时 | 消息区显示失败阶段、耗时和原因，不伪装成成功 |
| D08 | 快速重复发送 | 页面不会因一次点击产生两条相同用户消息或两个并行提交 |
| D09 | 切换会话后再切回 | 原会话消息顺序、角色、时间和运行轨迹完整 |

## E. 运行上下文与回放

| ID | 操作 | 预期 |
|---|---|---|
| E01 | 打开运行上下文 | 可见当前任务的运行阶段和时间线 |
| E02 | 展开模型阶段摘要 | 显示理解任务、分析约束、准备行动、验证结果等安全摘要；不展示未经处理的内部思维原文 |
| E03 | 展开工具调用记录 | 显示工具名、参数摘要、开始时间、进行中/完成状态、耗时、结果或失败原因 |
| E04 | 展开参数/结果/证据 | 参数、工具结果、证据或 receipt 可关联到同一轮次/调用 |
| E05 | 观察运行进程列表 | 能看到模型轮次、工具进程、脚本进程和当前阶段 |
| E06 | 观察子智能体列表 | 父任务、子任务、子任务状态及合并结果可区分 |
| E07 | 断开或重新打开运行上下文 | 已发生的事件仍可回放，时间线不从空白开始 |
| E08 | 刷新项目/重启应用后打开同一会话 | SQLite 轨迹、消息和工具调用记录仍在，顺序一致 |
| E09 | 观察候选/证据治理摘要 | 候选数量、冲突/待审、证据/receipt 数量有可见状态，未确认候选不冒充事实 |

## F. 项目应用面板

| ID | 操作 | 预期 |
|---|---|---|
| F01 | 打开项目应用面板 | 面板标题、版本和当前应用状态可见 |
| F02 | 点击“总览”标签 | 显示项目状态、应用状态和能力摘要 |
| F03 | 点击“内容与数据”标签 | 显示应用内容或数据信息，页面不报错 |
| F04 | 点击“资料来源/引用”标签 | 显示来源/引用区域，空状态也有明确说明 |
| F05 | 点击“运行入口/打开应用” | 应用启动或显示明确的未启动/错误反馈 |
| F06 | 点击停止、重启或运行管理按钮 | 状态在启动、运行、停止之间正确变化 |
| F07 | 点击项目应用面板关闭按钮 | 面板关闭，主区可继续操作 |
| F08 | 启动嵌入式浏览器应用 | 浏览器内容在应用内打开，不依赖 iframe；地址/状态可见 |
