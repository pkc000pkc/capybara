## 已确认的桌面闭环

1. **冷启动可回放。** SQLite/Trace 中的会话、工具结果、应用状态和证据收据在 Electron 进程重启后恢复。
2. **超时失败可解释。** 页面同时呈现超时标志、工具层/进程层耗时、进程是否收束、退出码、stdout/stderr 和失败原因。
3. **失败后可继续工作。** 超时后 Runtime 回到等待指示，后续请求可以正常完成。

## 新发现的缺口

- **工具失败后的模型重试过多。** 首次 `run_code` 参数错误和 `python` 命令不可用后，模型继续多轮重试，期间页面长时间保持“正在处理模型结果”。失败工具应更早进入明确的失败终态，或由 Runtime 给出一次性可用能力提示，避免把参数错误扩散成多轮无效调用。
- **失败协议仍不够统一。** 最终回复能基于多个收据重建过程，但时间线中的每次失败调用、重试原因和最终超时收据尚未以同一组 `turnId / stepId / callId` 在证据治理中展开核对。
- **默认超时策略未验证。** 本轮显式使用 `timeout_ms=10000`；项目显示的工具超时上限为 600000ms，默认 timeout 的页面表现尚未单独验证。
- **子智能体仍为 0。** 父子任务的非空运行态和合并结果仍缺页面证据。

## 下一轮建议

下一轮不必重复成功路径，优先做“工具失败后立即收束”的定向验收：构造一个可预期的权限拒绝或无效参数调用，确认 Runtime 是否在一次失败事件后停止重试，并检查失败调用、重试原因和最终回复的关联 ID 是否完整。
