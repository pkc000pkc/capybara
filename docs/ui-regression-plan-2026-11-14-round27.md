# UI 黑盒回归计划（Round 27）

日期：2026-11-14  
范围：项目应用更新失败、回滚和状态表达

## 目标

验证项目应用在更新成功、更新失败并自动恢复旧版本时，页面状态、运行实例、错误原因和版本信息保持一致，不能把“已回滚”显示成“已更新”。

## 前置条件

- 使用最新 `desktop:build` 构建启动 Electron。
- 打开一个已登记且存在项目应用 manifest 的本地项目。
- 应用至少有一个可启动版本；测试失败路径需要准备一个健康检查必然失败的新版本。

## 用例

| 编号 | 页面操作 | 预期 |
| --- | --- | --- |
| R27-01 | 打开项目应用面板，查看总览、版本和实例状态 | 页面显示当前版本、运行状态、地址/健康状态，控制按钮与状态一致 |
| R27-02 | 启动应用并执行“更新” | 成功更新时显示新版本，实例保持 running，运行地址和健康状态可用 |
| R27-03 | 让新版本健康检查失败后执行“更新” | 页面显示“更新失败，已回滚”，包含失败原因和恢复版本；不显示“应用已更新到新版本” |
| R27-04 | 更新失败后重新打开运行上下文 | 应用收据/运行轨迹保留 update 失败与 rolled_back 事实，版本指针和实例状态一致 |
| R27-05 | 点击停止、重启、关闭应用视图 | 停止会收束实例状态；重启恢复健康实例；关闭视图不误停进程 |

## 判定规则

- 页面显示与 Runtime 返回的 `operation`、版本 ID、健康状态一致。
- 更新失败后必须能区分：新版本失败、旧版本恢复成功、恢复失败。
- 任何失败路径都必须保留可回放收据和失败原因。
